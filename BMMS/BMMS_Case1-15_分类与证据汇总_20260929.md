# BatchMatmulMaxSum：Case1–15 分类与证据汇总

更新：2026-09-29。以当前已接受主线 **v12_baseline_r41.asc** 为准。

后续补充（2026-10-01）：Case12新报告给出K=1536、TB=false、pN=2等信息；实际planner离线枚举表明，若比赛传入20核，则M=1280。详细证据边界和优化影响见[Case12新探针复核](BMMS_Case12_新探针复核与离线计划_20261001.md)。下表保留9月29日的历史口径。

本文区分三件事：**输入形状类别、源码的 Family 分类、当前执行路线**。三者不等价；同一个 Family 可以走不同 kernel，同一个原始路线也可能已被后续特化接管。

版本记号：`Rxx` 表示 V11 历史版本，`v12_rxx` 表示 V12 版本。例如有效的 Case8 `R43` 与后续无收益的 `v12_r43` 不是同一个实验。

## 1. 记号与证据口径

逻辑运算为：

```text
A: [B, M, K]
B: [B, K, N]
C[b,m,n] = sum_k A[b,m,k] * B[b,k,n]
Y[b] = sum_m max_n C[b,m,n]
```

上面是逻辑维度；输入实际存储还受 TA/TB 转置标志影响。正文的 `B` 表示 batch 数。

- **已确认**：有归档的有效阳性校准、条件探针及源码条件支持。
- **队友结论**：采用用户转述的最新探针区间，但本地未独立取得全部原始探针与执行记录。
- **工作画像**：来自历史诊断报告，或与已接受优化的元数据范围一致；不能当成已恢复的精确输入。
- **未确认**：缺少能区分候选的有效信号，尤其不能把一次“没有明显变化”作为路线排除证据。

所有点的精确 dtype、TA/TB 和完整 shape 都没有在本地直接读取。下列耗时统一采用最近一次 r44 正常反馈整图，不拼接各轮最小值。r44 是诊断版，Case12 为 MISS；正式主线仍为 r41。截图本身没有平台源码哈希，版本归属沿用对话关联。

“当前路线”是结合源码、诊断和历史收益形成的执行归属，不代表已经取得每个隐藏测试点的实际 profiler kernel 名；报告级画像相关路线仍需按表中的证据边界理解。

## 3. 按计算结构归为八组

| 组 | Cases | 共同问题 | 不能混淆的地方 |
|---|---|---|---|
| 纯点积 | **1** | 一个输出、短K、固定指令及归约开销 | 没有二维行Max，也没有跨核归约 |
| 极小矩阵 | **2/3/4** | 小M/N、短K；向量打包、点积、Max/Sum组织 | 2是单batch；3/4是多batch工作画像，不能直接照搬并行策略 |
| 多batch固定短K | **5** | 小C矩阵、K128、每batch独立 | 已走Native Cube，区别于2/3/4的工作路线 |
| 小空间中K | **6/7** | 几何规模可能接近，可作为路线对照组 | 7已确认R03家族；6实际路线未确认，不能写成已证明的generic/R03对照 |
| 非对齐大矩阵 | **8** | padding、布局整理、宏块吞吐 | 与9–12的原生对齐大矩阵不同；当前已不应简单称为“generic慢路径” |
| 对齐大矩阵 | **9/10/11/12** | Cube宏块、数据搬运、任务划分、最终归约 | 9/10较短K，11较长K，12宽N；当前11和12已走不同特化 |
| 单batch固定短K矩形 | **13/14** | K128、空间矩形、Native消费者与调度 | 窄N和窄M的归约方向不同，不能当成完全对称的优化问题 |
| 小输出超长K | **15** | 原空间任务不足，以K并行补充并行度 | 必须先合并完整K的点积，再对N取max；不能对各K分片先max再相加 |

这八组是便于研发的结构分组，不是八个设备kernel。源码还会按dtype、布局、K常量和门槛实例化多个入口。

## 4. 需要纠正的几个旧分类

### 2/3/4：M/N小不自动等于Tiny/Resident

当前源码的主要门槛包括：

```cpp
UseTiny = M*N <= 16 && K <= 1024 && M*N*K <= 8192;
UseResident = M <= 32 && N <= 64 && K <= 128
           && M*N <= 256 && M*N*K <= 16384 && (M+N)*K <= 8192;
```

例如`16×16×128`的乘积是32768，不满足Resident工作量门槛。旧诊断报告称2–4“一定在Tiny/Resident”过强。点2的r03只接管实际满足原Tiny/Resident的范围；点3/4仍需核对实际分支。

### 5/13/14：是三种几何，不是同一个优化目标

- **5**：多个小矩阵，完整batch可以由一个消费者完成。
- **13**：工作画像为大M、窄N，主要沿M铺开；R49条件要求`pN=1`。
- **14**：工作画像为窄M、宽N，可能涉及N方向分片合并；精确`pN`未知。

13/14的可靠旧探针已经给出M/N都大于32，故按当前分类器属于`Dense_SmallK`。不能继续使用旧报告中的`N=32→ShortN`或`M=32→ShortM`作为当前已确认分类。

### 6：保留假说，不能伪装成已经定位

历史报告给了一个很具体的Generic MidK画像，但我们没有完整独立复核其原始Universal/A01证据。本地记录中，多次“改成单组没有明显响应”不能排除原来就只有一个组的路线。

因此Case6的正式状态应写为：**暂定Dense_MidK；实际route待确认**。下一步优先恢复路由，而不是继续细分其M/N/K。

### 8：三维全不对齐与至少一维不对齐不同

历史报告声称`M%16!=0 && N%16!=0 && K%32!=0`。当前R43/r19资格只要求：

```cpp
(M%16 != 0) || (N%16 != 0) || (K%32 != 0)
```

R43和r19的明显实测收益支持该特化方向，但不能用这个OR条件反向证明三项都成立。这里保留“非对齐大矩阵”分类，不杜撰具体余数或物理布局。

### 9/10：边界K=1024影响Family名称

两点范围是`1024≤K<1536`，并未排除1024。当前分类器在`K<=1024`返回`Dense_MidK`，在`K>1024`返回`Dense_LargeK`。工程上可统一称“R06短K大矩阵簇”，但不能把源码Family无条件记成LargeK。

### 11/12：不是K越大就必然越慢

11的K比12长，但12的N明显更宽，完整M/N/K工作量不同。最新分类清楚地区分：

```text
11：较均衡空间 + 更长K + r41宏块展平
12：宽N矩形   + 相对较短K + r30原网格
```

Case12未命中r41，只能说明该优化要求的峰值宏块数量严格下降不成立，不能推出负载时间均衡、没有优化空间，或已经确认某个精确pM/pN。

### 15：空间只有一块，不等于实际只用一核

原空间任务数`B*ceil(M/64)*ceil(N/128)=1`，但Split-K用8或16个K分片形成并行。L06没有区分S=8/16，也不能由历史报告缩小成`M,N都只在32/48/64`；应保留表中的强探针范围。

## 5. 尚缺的信息与最少诊断方向

| Cases | 最影响下一步的信息 | 是否需要先精确shape |
|---|---|---|
| 1 | 精确K及实际短向量流水开销 | 不需要，可以覆盖13个合法K |
| 2 | Tiny还是Resident、布局、动态循环/归约成本 | 不需要先完整二分M/N/K |
| 3/4 | 目标小矩阵路线是否命中、每AIV负责多少batch | 优先接管谓词/route，随后才按需要拆batch或布局 |
| 5 | batch数与核数关系、完整batch执行的实际固定开销 | 可以先覆盖四种M/N组合和B边界 |
| 6 | **实际route** | 应先定位；此时精确shape收益较低 |
| 7 | 当前batch独占下的生产者/消费者关键开销 | 原始形状范围已足够做同域实测 |
| 8 | NZ整理与计算阶段各自占比、实际布局相关行为 | 优先测机制，不继续无目的二分 |
| 9/10 | 当前plan、布局、加载与计算的瓶颈 | 先合成簇profile；仅在方案依赖时补plan门槛 |
| 11 | r41后剩余瓶颈 | 当前区间已较清楚 |
| 12 | 加载/调度交互、实际plan及布局 | 比进一步精确K更重要 |
| 13/14 | 真实窄维度、M/N分片及消费者成本 | 只补能区分不同方案的条件 |
| 15 | 当前Split-K合并与生产流水占比 | 已有范围足以继续研究，无须先求精确shape |
