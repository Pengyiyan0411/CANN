# D24：按可观测路径分组诊断

2026-09-27。用户已纠正两张截图的版本：它们是 **R23_SPLIT_K**，均 15/15 Pass，
Case15 均为 15.18 μs。保留 R23 为当前提交基线，冻结原 R14/R23 源码；本包不产生新的冲榜内核。

## 判断更新

历史 R14 的 Case15 截图为 36.25 μs，R23 两次为 15.18 μs，时间减少约 58.1%，约 2.39 倍加速。
不是同轮相邻 A/B，不能对其他点的小幅波动做收益归因；两次显示相同也不表示设备零方差。
但 Case15 的差异幅度、重复结果与 R23 的局部代码作用域共同支持 Split-K 有实际收益。
本轮不继续旧 A–C 扫描，也不要求补旧结果。

Case7 旧 C512 不变 **不能推出 K<512**。用户补充 A01 只将它从约 11 推到 13.11 μs，
这个 bypass 信号太弱；而 P02 单组压力为 32.83 μs，适合用作条件编码。
保留 K≥256、32 对齐的 R03 已知域，把 K 的上界重新记为未知。

## 每次只干预一个实际路径

所有文件都是在 R23 上修改 host 的独立完整提交。顺序继续为
`Macro → Split-K → R03 → Tree/Native → 剩余 dispatcher`。
条件只在原路径已经选中之后判断，不能重算一个宽泛 family 便误伤更早返回的路径。
设备函数、布局、数学计算和同步协议的源码全部不变。

Native / R03 / Macro 压力计划完整更新为：

```cpp
p.pM = 1;
p.pN = 1;
p.tasks = p.B;  // 保留每个 batch，不能留下旧 tasks 或硬写成 1
p.blocks = 1;
```

修改后才按 p 计算 ring、partial/workspace 大小与 launch 参数。
生产者和消费者都使用同一个 p，所有 batch 由单组顺序处理。
不减少计算范围、不重复输出 tile、不在数据或输出里编码诊断信息。

Tree 压力只将原 p.workers 改为 1，保留 chunks/padded/direct。
剩余 dispatcher 压力只在最后那次 fallback 调用中传 1 核；早期返回的五条路径都不受影响。
诊断文件可能故意变慢，应与冲榜版分开保存。

## Native：一次结果同时观察 5 / 13 / 14

| 文件 | 在 Native 路径内执行单组压力的条件 |
|---|---|
| N01_K_EQ32 | K==32 |
| N02_K_EQ64 | K==64 |
| N03_M_LE32 | M≤32 |
| N04_N_LE32 | N≤32 |
| N05_B_EQ1 | B==1 |

N01 阳性 → K32；N01 阴性、N02 阳性 → K64；两者阴性且 Native 阳性对照有效 → K128。
两个 K 探针同时阳性与互斥谓词矛盾，不能强行解码。

N03/N04 的阳性组合：`是/否→ShortM`、`否/是→ShortN`、`是/是或否/否→Dense`。
这个分类只在已经进入 Native、排除了 Tiny/Resident 的条件下成立。
`C00_NATIVE_1G` 是本包不带 predicate 的 Native 阳性对照。
已提供的 P03 结果足以指导先跑 N01–N05；如果新条件结果模糊或要用双阴性排除 K32/K64，
再用 C00 确认新基线上压力信号仍成立。它不是重跑旧 C 阈值系列。

## Case7：用 R03 单组压力编码，保留空间并行线索

| 文件 | 在实际 R03 路径内的条件 |
|---|---|
| R7_01_M_LT128 | M<128 |
| R7_02_N_LT256 | N<256 |
| R7_03_MACRO_OCC_LT_CORES | B×ceil(M/128)×ceil(N/256)<cores |
| R7_04_K_GE512 | K≥512 |
| R7_05_K_GE1024 | K≥1024 |

前三个是 R14/R23 当前 macro eligibility 中尚可能失败的结构条件，彼此可以同时成立。
在有效 R03 输入和有效压力对照下，三个都阴性与 residual 定义矛盾，应先查测量/版本/路径。
macro_occ 是可分配的宏块数量，不等于当前 R03 实际 launch blocks，也不是 profiler 的占用率。

R7_04/05 的可靠结果：否/否 → 256≤K<512；是/否 → 512≤K<1024；是/是 → K≥1024；
否/是不可能。所有区间继续要求 K%32=0。
`C01_R03_1G` 是新的 R03 阳性对照；若它不再有强响应，先停止用 R7 阴性解码，
因为 R23 的更早 Split-K 分支可能改变某个点的可观测路径。

## Case15：在已启用的 Split-K 内干预

旧 R03 bypass 在当前 Case15 上不会执行，继续使用它会得到没有信息的阴性。
新 L 系列在 R23 guard 已成功后、分配 workspace 前，用条件式单分片：

```cpp
if (predicate) {
    p.splits = 1;
    p.blocks = B * p.mTiles * p.nTiles;
}
```

其余全为 R23 的同一消费者、固定 K 求和方式和发布协议；S=1 时自然没有 K 合并加法。
`L00_K1_CONTROL.asc` 与上轮 R23_K1_CONTROL 字节一致，是新基线下必要的 K1 对照；
不能预设它一定是旧 R14 的 36–38 μs。

优先做 **L00，然后 L05_SPATIAL_EQ1**。L05 的 predicate 是 `B*mTiles*nTiles==1`。
如果 L05 恢复到 L00 的明显慢状态，在本 guard 中可同时得到
`B=1、M≤64、N≤128`。三个因子都是正整数，所以这是代码和正响应给出的联合结论，
不同于此前由 P02 无响应作出的间接猜测。

如果 L05 可靠阴性，再分别用 L01_B_EQ1 / L02_M_LE64 / L03_N_LE128。
L04_MN_LE4096 区分旧 semantic family；L06_SPLITS_GE8 判断原 planner 的 S 是否至少为 8。
L06 读取的是被修改前的计划，不按分片后的值判断。
原 R03 tasks 在这个选中域里等于 B*mTiles*nTiles，host 穷举核对该关系；
它与当前 launch groups=`spatial*S` 必须分开记录。

## Case6：复用已提交结果，剩余路径再补

先同时观察 Native N/C00、R7/C01、L00 对 Case6 的影响。有强响应就先锁定相应实际路径。
仍未定位时，按需依次提交 X6_01_MACRO_1G、X6_02_TREE_1W、X6_03_FALLBACK_1CORE。
这三份分别只作用于 Macro、Tree、最后的通用 dispatcher。与 C00/C01/L00 合起来覆盖六条顶层分支。
Fallback 阳性只能锁到最后 dispatcher，不能直接说它是哪个实际 kernel；还可能是 Resident、
连续 Skinny、Dot/Tiny、高层 Matmul 等，下一批再区分。

所有压力都无明显变化时记为未知，不能把路线全部排除；该输入的原计划可能本来就近似单组。
TLE、编译失败或精度失败也不能当作一个 shape bit。

## 读数和提交节奏

不做跨 case 全局缩放，不拼接历史最低用时，不通过动态“最优用时”列归因。
保留完整 15 点结果及准确文件名。先看正确性，再将响应记作阳性 / 阴性 / 不确定。
阳性要明显离开相邻控制波动，并接近对应压力对照；阴性必须有该点有效的压力对照。
约 11→33、17→99 的历史信号用于选择探针，不作为新结果的硬编码阈值。

推荐先完成 N01–N05 和 R7_01–R7_05；Case15 插入 L00→L05。
如果条件结果已经给足下一步信息，停止该组。C00/C01、其余 L 和 X6 是按结果展开的文件，
不是要求一次跑完全部 23 份。旧 A–C 不进入本包。

## 结果到下一轮优化的映射

- Native：确认 K/family/B 后，才决定短 N 的紧凑存储/归约、短 M 的 A 复用，或 Dense 的搬运复用。
  不把之前宽列/大块无收益的尝试直接重命名再提交；先确认目标是否实际进入候选条件。
- Case7：M 门槛失败侧重保留 N 空间分核；N 门槛失败侧重 M 分核及窄 N 搬运；
  只有宏块数量不足时，避免把已有细粒度空间任务强行合成更粗的 macro。K 区间决定 K 块长度消融范围。
- Case15：优先比较 K1 与 Split-K 并行收益。如果联合几何为单空间任务，下一版重点是
  **紧凑 N 宽度的 partial 合并**与受控 S 消融：当前消费者固定 128 列、先补零再加，
  小 N 会处理多余 UB 元素。先减少这段确定的工作量，再考虑会增加屏障的多 AIV 合并。
  这只是下一版候选设计，尚未作为新的性能代码交付。
