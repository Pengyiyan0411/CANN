# R28_COMPACT_SPLITK

从冻结 R25 增加一个针对 Case15 已确认元数据范围的策略，保留 R25 的 Native 优化。先提交 **R28_COMPACT_SPLITK.asc**，对照文件为原字节 **CONTROL_R25.asc**。每份均为完整独立源码。

入口要求：原 Split-K eligible、B=1、M≤64、N≤128、M×N≤4096、原 splits≥8；原资格还要求 M/N 为 16 的倍数、K∈[4096,8192] 且 32 对齐、FP16/BF16。满足条件时启用紧凑 N 行距，并将多个 K 分片的结果用一次跨片 DMA 搬入每个行条带。保留原 K 划分、逐元素 K 加法树和同步协议。

典型逻辑工作量：M32/N64/S8 的归并 DMA 调用由 16 次降至 1 次，K 合并的向量元素数由 28,672 降至 14,336。这是源码工作量，**不是已测加速比**，也不表示已经知道 Case15 的精确 M/N。

本地验证：R25/R28 各 76 次实际源码 CPU 模型运行，输出逐位一致；223,010 组主机分派检查通过，包含 93,840 组非目标完整启动记录相同；四类设备源码故障和一类越界分派条件被检出。没有本地 CANN 编译或 NPU 运行，平台兼容性、精度和性能仍需实测。详情见 DESIGN.md、CPU_CHECKS.json、HOST_CHECKS.json。

平台验收：保留全部 15 点结果，先看编译和正确性，再比较 Case15。为了排除已有波动，按 R25→R28→R25→R28 交替测，观察 Case5、13、14 及其余点是否出现稳定退化；不能用诊断包中 Case5 的约 7 μs 作为 R25 对照。R25 既有 Case5 为 6.60/6.45 μs、Case15 为 15.30/15.03 μs，仅作历史参考。

R28 尚未晋升为性能基线；Case6 未定位，无法承诺其输入一定不满足新策略的条件。对所有不满足条件的输入，旧内核源码、计划、workspace 和启动记录保持一致。
