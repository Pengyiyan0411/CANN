## 只替换消费者

新增分派位于原 `native` 分支中、R25 分派之前。条件为：

```cpp
B == 1 && K == 128 && M > 256 && M <= 8192 && M % 16 == 0
&& (N == 48 || N == 64) && pN == 1 && blocks > 1
```

沿用入口已经算好的 `bmms83::MakeNative` 计划，直接调用原 `bmms83::SmallKProducer<T,TA,TB,128>`。M/N 分片、核组数、MMAD、原 TM64/TN128 ring、每四 tile 的 READY/FREE 通知及 workspace 尺寸保持原样。

消费者利用 N 只有一个完整面板的条件：

1. 从 TN128 的原 ring 中读取实际 48/64 列，紧凑存入 UB；不读取 padding。
2. 直接对完整行做 `WholeReduceMax`，写入原 M 位置；省掉负无穷初始化、通用 N 面板 Max 累积、128→64 列折叠及 running Max。
3. 保留原 AM 分段、逐 tile 行最大值回写、一个 `SyncAll` 和完整 M 的一次 `ReduceSum`。没有改成局部求和或 atomic。
4. 完整 packet 和最后不足四 tile 的 packet 都按原协议归还两侧 AIV 的 credits。

这是对“原生产者配窄 N 消费者”的消融。仍保留 GM 行最大值及全局汇合，因此不会把本轮结果夸大成整个归约结构的结论。收益未知，可能消费者并非主要瓶颈。
