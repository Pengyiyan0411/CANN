## 分派范围

仅接管 `B=1、2<=M,N<=16、32<=K<=128、K%8=0` 且原分类为 Tiny/Resident 的输入。在上述范围内，最后一个条件等价于 `M*N*K<=16384`。

精确 M/N/K、TA/TB 和 dtype 尚未知，所以同时支持 FP16/BF16、四种转置组合、非16对齐的 M/N，以及所有合法的 K。仍按真实元数据选择策略，不依赖 case 编号。

该条件排除 B>1 的点3/4/5、R48 点7、R43 点8、R49 点13、点14和长 K 的点15。它也排除 M/N 为1的输入。报告范围内不满足 Tiny/Resident 的形状继续原路线，例如 `16×16×128`。

## 改动

原 Tiny/Resident 用单个 AIV 逐行计算，并在行内和行间多次同步。R50 将 A/B 向量一次整理好，把全部 M×N 点积的乘法、点积归约、逐行最大值分阶段执行；独立行写入不同 UB 区域，减少逐行同步。

- Tiny 仍使用原来每个点积的 `ReduceSum(K)`，每个点积分配独立 scratch。
- Resident 保留 Kp=128 时的两半相加，以及原 `WholeReduceSum` 的点积归约方式。
- 保留 FP32 乘法、行最大值、稀疏行结果最终求和，不切换 Cube 或低精度累加。
- 一个 kernel、一个 AIV、零 GM workspace、没有显式 host 同步。原单 batch Tiny/Resident 本来也是这一启动方式；本轮收益假设来自设备内部组织变化。

移除新增模块和唯一入口 hook 后，可逐字节恢复 R49；已有 kernel 和 planner 未改写。源代码隔离不代表二进制性能绝对隔离，仍需测评全部15点。

## 已完成验证

| 检查 | 结果 |
|---|---|
| 实际旧/新 device 源码的 CPU 模型 | 864 组对比，1728 次执行，全部逐位一致 |
| 布局与数据覆盖 | 两种 dtype、四种转置、Tiny/Resident、K尾部、负数/零/随机数据 |
| FP64 数学参考 | 最大绝对误差 `1.19209289551e-7` |
| 故障注入 | 故意破坏 TA gather 步长，被测试检出 |
| 实际 host 分派源码 | 85,354 组；21,884 组目标命中，63,470 组非目标记录完全不变 |
| 特定旧策略保护 | 点5相关元数据2440组、R48 504组、R49 42组、Split-K 310组、R43 padded 64组 |
| 全目标域 UB 公式枚举 | 每块按32B对齐后峰值146,560字节，低于192KiB检查预算 |

CPU 模型检查算术、地址与初始化，不能验证真实 Vector 流水、工具链支持或时延。host 测试用启动记录器代替设备执行；原 Tiny/Resident 的计算另外由 CPU 源码模型检查。UB 预算结果不代替设备编译资源报告。CPU_CHECKS/HOST_CHECKS中的未上板标志描述生成这些记录时的本地验证范围；后续用户测评另存于反馈目录。
