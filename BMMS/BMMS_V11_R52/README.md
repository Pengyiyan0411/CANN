## 点1与点2的相似和区别

历史报告的点1工作画像为 `B=M=N=1、32<=K<=128、K%8=0`。点2为单batch的小二维矩阵。它们都适合短向量计算，但点1只有一个点积，点2还要对N取最大值、再对M求和。

该形状画像来自历史报告，精确K和dtype尚未确认。R52覆盖全部13个合法短K和两种输入dtype，不假设某一个隐藏形状。M=N=1时四种转置的实际存储都退化为连续K元素，原Dot也不区分转置。

原Dot已经没有gather、矩阵中间结果或跨核归约，不能把点2的整套行缓冲搬过来。R50两次点1为 **2.41/2.42微秒**，本轮从动态配置与指令组织入手，不承诺达到平台显示的1.22微秒。

## 改动

接管条件严格为 `B=M=N=1、K=32,40,...,128`：

1. 每个dtype/K采用编译期常量设备入口，共26个变体；每次调用只启动其中一个，使用1个AIV。
2. 去掉原Dot面向任意B的batch循环和block索引；UB尺寸、搬运长度及归约长度都由常量K给出。
3. 当K为16的倍数时，A/B在输入UB中没有间隙，合并两次Cast为一次 `Cast(2*K)`。对于40/56等尾部有间隙的K，保留两次Cast，避免读取未初始化padding。
4. 保留原FP32乘法和 `ReduceSum(K)`，不改变求和算法、不降低精度、不使用atomic。

两路DataCopyPad、TQue同步及精确4字节输出写回保留。它们是数据正确性所需的处理，本轮没有凭空假定可以省掉。全模块UB峰值2080字节，无workspace。
