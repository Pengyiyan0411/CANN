# Case15 之后的优先方向

> 本页为 r12 接受前的历史计划。当前已接受主线为 r12，Case8 候选为 r19；最新顺序见 [Case8 后续方向](NEXT_DIRECTIONS_r18.md)。以下“r03保持主线”等描述不再代表当前状态。

主线保持 `v12_baseline_r03.asc`。用户最新反馈：r07 的实际比赛收益被噪声淹没，不晋升。r08/r09 的 Native 局部求和和 B 常驻 L0 已在本地筛掉，不继续同类微调。

## 第一优先：完成 Case15 本轮结构对照

确认的范围已经足以开工：B1、M≤64、N≤128、MN≤4096、K4096..8192/32、原 Split-K S≥8。不再花比赛提交去细分精确 K。

- r10 检验整 K 分片搬入 L1、扩大容量允许的 L0 K 块，保留原单核合并。
- r11 独立保留原生产端，把完整 K 合并和 N max 分给按行分工的 AIV，再同步执行最终 M sum。
- 只有前两项各自有清晰收益且组合有必要，才做第三轮组合；每轮均从 r03 冻结源生成，不继承失败候选。

验收使用同卡、串行 NPU 任务、交替 A/B、A/A 噪声标尺、独立进程复验、未用于调参的尺寸和四布局。合成用例无法代替真实 Case15，候选交付后仍需比赛全15点确认。

## 第二优先：Case8，先在本地分清阶段成本

理由：原 R43 把约91 μs 降到约62 μs，路由和尺寸域较明确，剩余绝对时间较大。R45 去冗余清零无收益，R46 SDK fast-main/tail 无收益，不能把这些假设换个编号重试。

当前路径是一个混合 kernel：AIV 整理 A/B → pack-to-Cube 同步 → R06 宏块计算 → 向量消费/归约。不是三次独立 kernel launch。

下一轮本地流程：

1. 生成真正命中原 R43 guard 的代表簇：B1，M/N∈[1024,2048)，K∈(1024,1280)、K%8=0，至少一个轴违反16/16/32对齐；两精度、四转置、不同余数。先记录实际分派和 pM/pN/blocks。此前 followup 的 M272/N520 示例不命中该路径，不能拿它当 Case8 验证。
2. 对完整路径采集 PipeUtilization 与任务时间。另建仅供本地分析的输入整理、预先整理后的计算消费对照，两个对照都验证对应真实数据；不把省略整理的诊断入口当比赛实现，不声称两段独立耗时能严格相加。
3. 整理/全量同步确实占显著比例，才尝试按 panel 整理与 Cube 重叠；先限定一个元数据域，建立每槽唯一拥有者及 ready/free 生命周期。
4. 若计算消费占主要时间，优先研究该域内部 C 块消费和独立 planner，保留全局 R06 规划，避免再次影响9–12。
5. 一次只检验一个主假设；跨布局收益混合则继续收敛或放弃，不直接提交全域版本。
