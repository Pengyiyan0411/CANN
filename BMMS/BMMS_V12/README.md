## 本版选择

集中修改Case12所属的R06大矩阵区间。已有证据足以确定其K区间，而精确M/N、dtype、转置组合和实际plan仍未知。因此按公开输入元数据分派，不硬编码某个猜测的完整shape，也不读取数据值或测试编号。

新分支条件为：

```text
B == 1
1024 <= M,N <= 8192，M/N均16对齐
1536 <= K < 2048，K为32的倍数
2 <= cores <= 64
同时满足原R06 eligibility及原family检查
```

点9/10已知K<1536，点11已知K>=2048，均不命中。点5/13/14的Native small-K也不命中。其余不满足条件的输入保留原分派。点6等尚未完全定位的测试点仍需完整测评确认，不能仅凭历史耗时保证绝不命中。

## 两项实际改动

**1. R06网格选择。** 原planner对部分新网格要求至少改善12.5%的估算工作量。本版从原plan出发，枚举至少使用75%核组的一波任务网格，接纳被该门槛遗漏的改进。

候选必须同时满足：每组最坏的macro数、每个K0切片的MMAD数、输出单元数、输入搬运工作量均不超过原plan；pN不增加。通过这些约束后依次比较MMAD、macro、输出、输入和pN，选出一组。没有更好网格就保留原plan。不会统一强制某个pM/pN，不会扩展到点9–11。

这些是源码推导的工作量，不是硬件周期预测。网格变好也不能单独证明耗时下降。

**2. 消费端去除重复填充。** 原消费端先把微块和累积缓冲填成负无穷，再执行Max。本版用两个独立VECIN缓冲紧凑搬入实际列，直接合并有效数据；每个M块的第一个N块直接初始化行最大值，后续N块才做累积Max。

每个M微块仍只做一次行归约。没有为了去填充而增加归约行数。尾列根据实际宽度设置搬运跨度与归约mask，未写入的padding不参与运算。

沿用R52的原R06 Cube生产者、AM128/BN256、K1=256/K0=64、FP32累积、双槽ring协议、两个AIV的行所有权、一次全局同步及最后完整M方向ReduceSum。未引入Split-K或改变最终求和树。

- [CPU源码回放](CPU_CHECKS.json)：176次运行，结果与原消费端及独立参考逐位相同；检查ring读写、所有权、令牌回收、partial完整覆盖、尾块、全负数、零值和反向线程启动。

- 故意把紧凑DMA的GM行跨度改错，检查器捕获`uninitialized GM read`；交付源码及正常测试头文件已恢复正确版本。

- [文件审计](ARTIFACT_CHECKS.json)：移除唯一新模块和入口hook后逐字节恢复原R52；原R52和R43文件未改动。
