## r02：9/10的A面板复用

已有证据：9/10走R06，B=1，M/N至少1024且16对齐，K为1024..1504的32倍数。尚不知道精确M/N、布局、dtype和实际网格。本版只按运行时元数据与原plan分派，不读取数据值或测试点编号。

新路径要求：

```text
B == 1
M,N >= 1024
1024 <= K < 1536
原R06 Eligible及family条件成立
原plan的 floor(nTiles / pN) >= 2
```

保留原R52网格、AM128/BN256、K0=64、L0双缓冲、FP32累积、ring协议和整个RowMaxConsumer。对每个M宏块一次加载完整K的A面板到L1，供本N分片后续宏块复用；B继续双缓冲流入。为容纳完整A，B的K1从256改为128。最终归约及求和树不变。

A逻辑搬运量由`B*M*K*sizeof(T)*nTiles`降为`B*M*K*sizeof(T)*pN`；B逻辑字节量不变。这个公式描述本实现的GM→L1请求量，并不等价于外部显存实际流量或运行时间。

代价是B加载描述符及阶段同步次数增加，完整A预载也可能增加起步延迟。额外的N复用门槛排除每个分片只有一个宏块的情况。**当前没有9/10实际plan，因此无法确认两点是否都命中。** 若成绩不变，首先检查这个门槛及搬运/同步的收益抵消，不将其直接解释为硬件极限。

最大K=1504时，A1+B1申请516,096字节，小于512 KiB；L0A/L0B/L0C分别32/64/128 KiB。A增加独立ready/free事件，切换M块前等待旧A读取完成。未沿用R31的K0=128和L0单缓冲方案。

已知11的K≥2048、12的K≥1536，均不会进入新路径。其他未知shape的测试点仍须观察完整15点结果；范围外源码不变不能保证硬件测时逐次不变。

## r03：点2的短K特化

完全沿用R50入口：B=1，2≤M,N≤16，32≤K≤128且K%8=0，并满足原Tiny或Resident判定。13个K值分别编译期实例化，覆盖FP16/BF16和四种转置布局，共104个入口。

当K=32/64/128且操作数在K方向连续时：A的TA=false或B的TB=true，直接引用Cast后的float数据，省去相应索引生成、零填充和Gather。其它布局和需补齐的K保留原打包过程，仍获得K常量化。保持原乘积、行最大值、最终M求和及归约顺序，不合并改变精度路径。

M=N=1的R52点1路线不受影响。点2的精确K/TA/TB未知，免Gather是否生效取决于实际布局；不能预先承诺性能提升。更多编译期实例可能增加设备编译时间。
