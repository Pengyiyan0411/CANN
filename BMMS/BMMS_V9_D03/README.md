# D03：K128 + 双 L0C 的独立流水实验

提交文件：`D03_DENSE_K128_C2.asc`。整份替换官方 `code/kernel.asc`，沿用官方其他工程文件。它是尚未 CANN 编译或上卡的新实验，不能沿用 D01/D02 的 Pass 状态。

## 为什么是这一份

D01、D02均15/15 Pass，但最新同T分数分别28.2532、26.8647；P01历史耗时同T为32.0956。K64使点9/10/11/15更慢，点12却几乎不变，因此停止进一步缩小K的扫描。D03回到D01的K128，只检验相邻输出块的C缓冲依赖。

| 项目 | D01 | D03 |
|---|---|---|
| L0C | 一个32KiB槽 | 两个32KiB槽 |
| C复用等待 | 每块开始等待前一块Fixpipe | 同一槽再次使用前等待其Fixpipe |
| K stage | 128 | 128 |
| Plan、接管域、输入搬运、MMAD累加顺序 | 原D01 | 相同 |
| consumer、GM两槽协议、workspace、公开入口 | 原D01 | 相同 |

两个C槽分别持有独立的FIX_M信用；结束时只清空已使用槽，释放两份事件。C物理缓冲扩到65,536 B，环区FREE/READY信用没有省略。数据类型仍为FP16/BF16输入、FP32 C。

这不是M/N输入复用实现，每个输出tile仍重读对应A/B。若该实验仍不能恢复大幅退化点，下一主线转为真实输入复用；不继续围绕这一个等待扫参数，也不按隐藏点号写分流规则。
