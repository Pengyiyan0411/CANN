# D04：128×128输出块，增加B输入复用

下一次提交 `D04_DENSE_M128_N128.asc`，完整替换官方 `code/kernel.asc`。只提交这一份，保留官方其他工程。D04尚未CANN编译或NPU运行。

## 这次改了什么

从D03的64×128×K128计算块改成128×128×K128，同一B块服务的行数从最多64增至128。producer和row-max consumer一起使用128行消息；Plan按新M tile数量划分，GM环区和片上缓冲同步扩展。保留双L0C、完整K后才Max/Sum，以及原P01 fallback。

接管条件仍为FP16/BF16、四布局、M/N为16倍数且至少16、K为32倍数且至少256，原Tiny/Resident受保护。它不是按测试点编号选择分支。较小M、尾块或不同分核下的复用收益可能更少，甚至因空间并行度下降而退化；必须看完整15点结果。

另补充小输出块的K累加同步：`(mr/16)*(nr/16)<10`时每次Mmad后加`PIPE_M`屏障。该约束由[官方Mmad文档](https://asc.gitcode.com/api/SIMD-API/basic_api/cube_compute_ISASI/mmad_compute/Mmad.html)和固定CATLASS v1.4.0源码交叉核对；先前模型没有真实流水，不能依靠普通数值通过排除这种问题。此更改使D04与D03不只是一个常量差异。

## 已验证的机制

对同一个公开控制例`B=1,M=N=K=256,cores=1`，真实C++源码在CPU模型中执行并记录API搬运量：

| 项目 | D03 | D04 |
|---|---:|---:|
| 逻辑GM输入读取 | 786,432 B | 524,288 B |
| C输出块发布次数 | 8 | 4 |
| C写出字节 | 262,144 B | 262,144 B |

这里输入读取减少1/3是模型中该形状的逻辑字节计数，**不是HBM测量或提速承诺**。没有实现跨全部N的A常驻、完整2×2复用或K1/K0两级流水。

## 如何看下一次结果

当前三轮原生实验未恢复点9–12的大幅退化，P01仍保底。D04用于检验增加输入复用、减少消息数量能否恢复吞吐；直接对照D03并同时比较P01全表。不要仅看第15点，也不以全Pass代替性能判断。
