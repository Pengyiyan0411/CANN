# BMMS V9 提交实验包

本包是用户授权的多次平台评测实验，已实现真实 kernel 路径。**尚未 CANN 编译或 NPU 验证，且已知存在对抗数值反例，不能把它当作通过精度验收的最终版本。** 保留 P01 为历史对照，不覆盖其原件。

## 怎么提交

每次选择**一份** `.asc`，完整替换官方工程的 `code/kernel.asc`，沿用官方其余文件和编译方式。不把片段文件、CPU测试文件或整个zip当成 kernel 源码。

建议先提交 **D01 与 S01**，两份互相独立；返回结果再决定 D02 和组合版的用途。

| 顺序 | 文件 | 唯一实验目的 |
|---|---|---|
| 1 | `D01_DENSE_K128.asc` | 对齐大K输入改走原生完整K Cube producer + P01 row-max consumer |
| 2 | `S01_SMALL_NT_PAIR.asc` | 小输出、NT布局、长K改走Vector点积任务/K分片，hi/lo保留到最终Sum |
| 3 | `D02_DENSE_K64.asc` | D01通过后对照；路由和消费相同，只把K搬运/计算块128改64 |
| 后置 | `M01_DENSE128_PLUS_SMALL.asc` | D/S独立结果支持保留时再试组合；重叠域S优先 |
| 对照 | `P00_CONTROL_P01.asc` | 原P01逐字节副本；必要时用来判断同环境波动 |

组合版使用 `M01` 编号；旧 `next_stage/C01_K128_COARSE_M_GUARDED.asc` 已退役，不在本包内。

D01 编译失败或 WA 时保留完整日志，仍可独立测 S01；不要通过组合两条未验证分支掩盖失败来源。编译成功且15点全部通过之后再比较耗时；小幅差异需要复测，不能用失败点的用时算收益。

## 实际接管范围

**D01/D02**：FP16/BF16，四布局；M/N≥16且均16对齐，K≥256且32对齐，保护原Tiny/Resident。完整K在L0C中FP32累加后才送Max。空间划分优先B/M，仅不足时最小必要N分片；每个N片保留逐行max。其余继续原P01。

它们是原生分段K版本，没有外部CATLASS依赖；未实现设计中更复杂的K1=256/K0=64两级输入复用。每个输出tile仍重读对应A/B，不预先声称超过旧SDK主干。

**S01**：FP16/BF16，仅TA=false/TB=true（物理A[M,K]、B[N,K]）；M2..32、N2..64、MN≤256、K1024..8192且K%8=0，并要求原Cube空间任务不足核数。先用不同dot占满Vector，只有dot不足时才增加K分片。其余继续原P01。

S01不使用原子加法。每个任务写独占32B的hi/lo记录；固定顺序合齐全部K，再按高低分量选Max、补偿Sum，最后输出FP32。它修复了特定点积低位提前丢失例，不等于与完整FP64全域等价。

## 已做的检查与真实边界

- D128源代码CPU模型：208次dense运行；S源代码CPU模型：80次运行。
- D64源代码CPU模型：208次dense运行；合计496次、248对正/反线程启动顺序重复结果一致。
- 每个dense配置检查4,296组合法planner；CPU模型检查GM/片上边界、初始化、写者所有权、两AIV信用配对和局部事件计数。
- 上述有界数据中没有严格/组合误差失败。独立数学模型及已知反例另列，不以普通数据通过覆盖反例。
- CPU的ND2NZ/LoadData/Mmad/Fixpipe是明确的存储/运算模型，**不是CANN编译器或硬件仿真器**；无法认证真实指令、异步可见性和设备性能。

已知数值限制至少包括：D的单FP32 C在强消减时丢低位；S的两个浮点分量在更强的三尺度消减下仍可丢低位；BF16有限输入可能在FP32乘法中先溢出，即使最终FP64 golden有限。详见包内 `PRECISION_REVIEW.md`；复现脚本保存在工作区 `V9_impl/test_semantics.py`，源码模型结果在包内 `CPU_CHECKS.json`。本轮目标是通过用户可用的平台收集编译、真实精度及路线收益证据，**没有承诺15/15或预测提速倍数**。

## 返回什么结果

每份注明文件ID、提交编号、编译是否成功、15点Pass/Fail与各点μs。若有当前最优T也保留；不只给总分。截图可以，WA或编译失败请同时保留文字日志。

包内 `MANIFEST.json` 给出完整源SHA256。`RESULTS_TEMPLATE.md` 可直接填表；可选 `record_results.py` 接受JSON记录并冻结本包源hash、计算相对P01变化。计分仅在15点通过时计算，缺当次T则明确使用历史T，不能当成当前排行榜分数。
