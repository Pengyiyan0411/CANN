# BatchMatmulMaxSum V8.1：输入分类与分场景专用方案

> 本文是 V8 方案的分类设计补充，不是新的提交代码，也没有新增 A2 性能测量。
>
> 核心改变：从“介绍几种优化技术，再分配输入”改为“先给每种输入确定数学结构、物理访问、复用对象与结果归约，再选择专用实现”。
>
> 题面事实使用 [P]；前一版已有设计使用 [V8]；本文新增的分类、候选实现与实验顺序均为设计建议，不是测得的最优分界。公开资料使用 [R1]—[R4]，来源列在末尾。

## 1. 输入到底有几种格式？先分清四个层次

题面中外部数据格式只有 **连续 ND**，不是 ND、NZ、NCHW 等多种输入格式。NZ 等格式只可能作为实现内部的搬运/计算排布。[P，§3.3—3.4]

外部数值类型有 **FP16、BF16 两种**，两个输入必须同类型；输出只有 FP32。[P，§3.3—3.6]

两个 transpose 属性产生 **四种物理存储布局**。逻辑矩阵始终是 `X1[B,M,K]` 与 `X2[B,K,N]`，属性不改变数学意义。[P，§3.5]

| 本文代号 | TA=transposeX1 | TB=transposeX2 | X1 的物理 shape | X2 的物理 shape | X1 最内层连续轴 | X2 最内层连续轴 |
|---|---|---|---|---|---|---|
| NN | false | false | `[B,M,K]` | `[B,K,N]` | K | N |
| NT | false | true | `[B,M,K]` | `[B,N,K]` | K | K |
| TN | true | false | `[B,K,M]` | `[B,K,N]` | M | N |
| TT | true | true | `[B,K,M]` | `[B,N,K]` | M | K |

这里 N/T 是属性代号，不表示运行时必须执行额外的全矩阵转置。代码应沿原始存储直接取数，或在所需局部块搬运时完成排布转换。

因此，一般非退化矩阵有 **4 种布局 × 2 种 dtype = 8 组基本接口组合**。这不是 8 种全部输入形状，也不是需要机械复制 8 份完整算法。

形状空间还包含 `B、M、N、K`。题面范围为：

```text
1 <= B <= 64
1 <= M,N <= 8192
32 <= K <= 8192，且 K 是 8 的倍数
B*M*K <= 2^26，B*N*K <= 2^26
```

这些整数范围不是 15 个已知形状。Judge 有 15 个测试点，但现有截图没有公开各点的 B/M/N/K、dtype 和属性，不能把测试序号当成输入分类。[P，§3.4、§6；V8，§2]

**正确的分类对象：**

```text
数学结构 × 物理布局 × dtype × K 工作方式 × 并行规模 × 对齐特征
```

各维度分别决定不同问题，不应压成一个“总 FLOPs 多大”的判断。

## 2. 先固定地址公式，避免讨论中的 N/T 歧义

以下是逻辑坐标对应的元素偏移，不是字节偏移：

```cpp
x1_offset(b,m,k) = b*M*K + (TA ? k*M + m : m*K + k);
x2_offset(b,k,n) = b*K*N + (TB ? n*K + k : k*N + n);
```

`sizeof(input)=2` 时，实际字节偏移再乘 2。每个 batch 的基址分别相隔 `M*K`、`K*N` 个输入元素。[由 P 的连续存储定义推导]

| 布局属性 | 物理一行的长度（输入元素） | 相邻物理行跨度（字节） |
|---|---:|---:|
| X1，TA=false | K | 2K |
| X1，TA=true | M | 2M |
| X2，TB=false | N | 2N |
| X2，TB=true | K | 2K |

这张表有直接的性能意义：同样 N=8191，TB=false 会改变 X2 每一物理行的跨度；TB=true 时改变的是向量条数，单条向量仍沿 K 连续。二者不能只因为“都有 N 尾块”就使用同一个搬运策略。

同理，M 非对齐对 TA=true 的整个输入行跨度有影响；对 TA=false，主要改变 A 的行数。K 非对齐则直接影响 TA=false 的 A 行跨度和 TB=true 的 X2 行跨度。

公开的 A2 矩阵搬运资料也按 A/B 各自的 RowMajor/ColumnMajor 分开处理，而不是在同一个取数循环里只增加一个布尔条件。[R2、R3]

## 3. 数学上只有四大类，退化形状必须先单独处理

令 C=X1×X2，最终输出为 `Sum_M(Max_N(C))`。[P]

| 数学大类 | 精确条件 | 计算本质 | 最后需要的操作 |
|---|---|---|---|
| D：点积 | M=1 且 N=1 | 两条 K 向量点积 | 只沿 K 求和 |
| Q：单 query | M=1 且 N>1 | 一条 query 与 N 条 document 的点积 | 对 N 个完整点积取 Max |
| S：单 document | N=1 且 M>1 | M 条 query 与一条 document 的点积 | 对 M 个完整点积求 Sum |
| G：一般矩阵 | M>1 且 N>1 | 矩阵乘后两级归约 | 先 Max(N)，再 Sum(M) |

M=1 和 N=1 都常被叫作 Skinny，但它们的最后归约不同，数值风险和 partial 格式也不同，不能写成一个不加区分的性能家族。

### 3.1 退化后的真实布局数量会减少

- **D 类：**X1 的 `[1,K]`/`[K,1]`、X2 的 `[K,1]`/`[1,K]` 都是同一条连续 K 向量。四种属性组合在实际地址序列上等价，可归并到一个 Dot 实现。
- **Q 类 M=1：**TA 不再影响 X1 的地址序列，只需区分 TB。于是有两种真正不同的 bank 存储：`[N,K]` 和 `[K,N]`。
- **S 类 N=1：**TB 不再影响 X2 的地址序列，只需区分 TA。于是有两种真正不同的 bank 存储：`[M,K]` 和 `[K,M]`。
- **G 类：**四种布局通常都需分别审查搬运路径。

以上是地址公式的直接推导，不依赖任何计时假设。

**所以不考虑 dtype 和 K 等性能分档，仅在退化结构上已经得到 1+2+2=5 种基础数据流；一般矩阵另有 4 种加载组合。** 这比“所有 Skinny 走一条函数”更贴近实际问题。

## 4. 第一类：D / M=N=1，只做 Dot

### 4.1 合并什么，分开什么

四种属性组合可以合并；但 K 与 B 不应忽略。建议单列：

| 子场景 | 主要候选 | 首要比较 |
|---|---|---|
| K=32/64/128 | 固定长度 FP32 点积 | 原 Dot vs 静态长度归约 |
| K 为其他中小值，如40/96/136 | 真实 K 掩码或局部补零 | 通用归约 vs 合法静态块 |
| K 接近上限、B 小 | 一条完整点积，必要时比较分段 | 分段的汇合开销是否值得 |
| B 较大 | 不同 batch 分给不同 AIV，或一 AIV 循环多个 batch | 批次粒度与启动规模 |

**默认不启用 Cube，不分配 C 矩阵，不加入 Max(N) 或 Sum(M) 的空操作。** 这是首选设计，不是宣称任意 Dot 都已证明 Vector 最快。

K 分块可以在同一核内完成；跨核分 K 只在工作量足够大且精度、汇合成本均经验证时考虑。对于小 K，不能为了显示核占用而人为制造跨核归约。

### 4.2 数值与复用

输入按原 dtype 转 FP32；K padding 为零。同一次调用中的 UB 分配可复用，不跨调用缓存输入或答案。输出由唯一 owner 以精确 FP32 元素写入。[设计；沿用既有工程约束]

## 5. 第二类：Q / M=1，必须分成两种完全不同的 Max-GEMV

数学式：

\[
y_b=\max_n\sum_k q_{bk}D_{bkn}.
\]

TA 可以从内层算法选择中消去，但仍应接受并校验官方输入属性。

### 5.1 Q-K：TB=true，bank 存储 `[N,K]`

每个 document 是连续 K 向量。

```text
q[K] 在 UB 中驻留
    ↓
每次加载 D[N_tile,K]：若干连续向量
    ↓
每条向量完整 K 点积，FP32 累加
    ↓
本核更新 scalar_max
    ↓
需要多核时，最终对各核 scalar_max 取 Max
```

这里可以比较固定 K 的批量 Dot，减少每行单独调用通用 ReduceSum 的标量控制开销。N 大时优先沿 N 分配工作，不必先拆 K。

**本分支特有的缩减机会：**每个 worker 已经算完其所有 N 范围的完整 K 点积时，可以只写一个 local_max，而不是把所有 N 个点积写到 GM。合并 Max 不需要再次读取完整点积分布。这个优化不能不加区分地移到其他家族。

B 足够大且单个 batch 工作不大时，比较一 AIV 独占一个 batch，直接写最终 y，无跨核合并。

### 5.2 Q-N：TB=false，bank 存储 `[K,N]`

每一物理行是同一个 k 对应的全部 N 元素。沿 N 是连续访问，固定 n 的 K 点积则跨行。

首选比较两种独立实现：

**Q-N-Lane：输出 N 作为 SIMD lane。**

```text
acc[N_tile] = 0
for 完整K的各K块:
    搬入 D[K_tile,N_tile] 局部矩形
    for k in 当前K块:
        acc[:] += q[k] * D[k,:]
# 完整K结束后才允许Max
local_max = max(local_max, max(acc))
```

它不需要把每条 document Gather 成连续 K 向量，但会付出 K 循环、标量广播和持续输出累加的成本。可以比较多路 FP32 accumulator 后固定合并，减轻长依赖链；任何累加树变化都需重新验证误差。

**Q-N-Pack：合并搬运后局部重排。**

搬入 `K_tile×N_tile`，在 UB 中整理成适合批量点积的局部排布。比较重排成本与 Lane 循环成本，不能先认定转置一定划算。只做局部转换，不增加全矩阵预处理 kernel。

较大 K 或较大 N 时，还应保留薄矩阵 Cube 作为第三个基准。

### 5.3 为什么二者不能只共用一条 Skinny 算法

`[N,K]` 的自然 Vector 组织是“若干独立的 K 归约”；`[K,N]` 的自然组织是“若干连续 N lane 上的 K 累加”。一个偏行内归约，一个偏跨 K 的向量更新。A2 GEMV 公开实现也区分 RowMajor 与 ColumnMajor 的这两类组织方式。[R1]

## 6. 第三类：S / N=1，两种 Sum-GEMV，与Q类分别验收

数学式：

\[
y_b=\sum_m\sum_k A_{bmk}d_{bk}.
\]

此时 N 上的 Max 是长度 1 的恒等操作；实现中无需执行真正的 Max，但仍先完成各行 K 点积。

### 6.1 S-K：TA=false，bank 存储 `[M,K]`

`d[K]` 驻留 UB，批量加载连续的 A 行，每行得到一个 FP32 点积。M 大时可以沿 M 并行。

默认保留“每行点积→固定树 Sum(M)”作为可靠基准。是否每个 worker 先汇总本地行和再写 scalar，必须单独验收：在实数数学上可行，但会改变浮点求和的分组，尤其是正负相消输入。

**不能因为 Q 类能安全地用 local_max 压缩，就假定 S 类 local_sum 的精度行为完全一样。** Max 和 Sum 的舍入性质不同。

### 6.2 S-M：TA=true，bank 存储 `[K,M]`

每个 k 对应的一段 M 连续。首选比较：

```text
acc[M_tile] = 0
for 完整K的各K块:
    搬入 A[K_tile,M_tile]
    acc[:] += d[k] * A[k,:]
# 完整K结束
保存逐行点积 / 经过验证的局部求和
最终固定顺序Sum(M)
```

局部重排成 `[M_tile,K_tile]` 后做批量点积是另一候选；若采用 Cube，同样必须独立比较转置 A 的加载效率。

### 6.3 第一轮明确不做的重排

不先计算 `sum_m A[m,k]` 再与 d 点积。虽然实数代数等价，但它改变题目参考计算的阶段与浮点累加树。在已有全负大 M 误差警告尚未充分处理前，不应同时引入该变化。[V8，§8.3]

## 7. 第四类：G-small，输入与中间工作区可驻留UB的小矩阵

不能只以“输入字节数小于 UB”判断可行。预算应包含：原16位输入、FP32转换、副本或打包区、积/点积区、索引、row max、最终归约scratch，以及缓冲阶段数。

第一轮延续 V7 Resident 的已实现范围作基准：

```text
M<=32, N<=64, K<=128
M*N<=256
M*N*K<=16384
(M+N)*K<=8192
```

这些是历史候选门槛，不是理论上限，也不是已测出的所有布局的最优界线。[V8，§7.2]

### 7.1 四种布局的局部计算候选

| 布局 | 可以利用的连续性 | 首要候选 | 必须计算的附加成本 |
|---|---|---|---|
| NN | A 沿K，X2沿N | 重排X2局部块后批量Dot；或按k更新短输出行 | X2局部Gather/重排，K循环 |
| NT | A与document向量都沿K | 批量内积，复用同一A行服务多个document | dot归约、输入广播，不应预设必定最快 |
| TN | 同一k的A[:,k]与X2[k,:]都连续 | 小输出块按k更新外积；与Cube/重排方案比较 | 输出acc占用、广播、K发指令成本 |
| TT | A沿M，document沿K | 局部整理A成连续K行，再做批量Dot；Cube对照 | A重排与索引成本 |

这里“外积更新”指一般数学组织 `C_tile += A_tile[:,k] * X2_tile[k,:]`，不是声称某个名为 OUTER_PRODUCT 的 SDK 模板在当前环境一定可用。

B 大时天然有独立任务；B=1时，哪怕输入很小，复杂Gather或标量循环仍可能比小Cube慢。需要两种 B 区间分别比较。

## 8. 第五类：G-shortM，少量query行、多document列

代表设计用例：`(B,M,N,K)=(1,8,4096,128)`，不是任何隐藏测试点的身份。

与M=1相比，这里有多个query行，不能只保留一个 scalar_max：必须为每个 query 保留 `row_max[m]`。

### 8.1 复用对象

**优先考虑 A 的全部少量行驻留，流式读取 X2 的 N 面板。** 同一document块服务所有query行，不把M行拆成M份互不共享输入的GEMV。

- NT：两类向量沿K连续，比较多query批量Dot与薄Cube。
- NN：X2的N面板在每个k上连续，比较小M输出块的向量更新与薄Cube。
- TN：A沿M连续，局部广播适合一次更新多query行；K大时控制开销可能不利。
- TT：A局部转换只对少量query做一次，X2继续按连续K向量读取；比较该转换是否值得。

### 8.2 分核与归约

B较小时，沿N切分可以提供并行。每个worker必须输出这一N分片的 `partialMax[M]`；最后先按M逐行合并各N分片的Max，再Sum(M)。

不能写成 `partialScore=sum(partialMax)`，然后再从各worker的partialScore中取最大值。

薄Cube候选不能直接沿用M=64/128的大块，造成大量无效行。应根据实际短M选择少量较小M块；具体补齐、指令支持和吞吐以目标SDK验证为准。

## 9. 第六类：G-shortN，少量document列、多query行

代表设计用例：`(1,4096,8,128)`。

它与上一类不是简单交换变量，因为最终是 Max(N) 再 Sum(M)。

### 9.1 复用对象与相反的驻留方向

**优先考虑 X2 的全部少量document驻留，流式读取 A 的 M 面板。** 不应继续默认沿用A驻留、流式扫B的策略。

- NN：X2 `[K,N_small]` 是窄矩形，先一次性搬入并整理，再复用到大量A行。
- NT：X2是少数连续K向量，适合驻留后与连续A行批量点积。
- TN：A按k提供连续M块，可按k更新 `C[M_tile,N_small]`；比较Vector外积更新与窄Cube。
- TT：少数document沿K连续，可驻留；A走独立的转置布局加载器，不做全输入转置。

### 9.2 分核与归约

优先按B/M分任务，每个任务覆盖完整N，直接产生完整的逐行最大值。这样一般不需要跨核再次Max(N)，只需要固定顺序Sum(M)。

这里如果再把本来很小的N跨核切分，可能增加原本不存在的partialMax合并；只有明确的同形状计时收益才接受。

**这是必须分开两类长宽矩阵的关键原因：**短M通常是A驻留、按N补并行；短N通常是X2驻留、按M并行。

## 10. 第七类：G-smallOut-longK，小输出但K长

代表设计用例：`(1,16,16,8192)`。M/N虽然小，计算不属于轻量Resident。

这类的首要问题可能是只有少数输出块、可用核难以填满，而不是C的体积。

独立比较三个候选：

1. 一个/少量计算组完成完整K，尽量减少控制与汇合。
2. 更小的M/N计算块，增加独立输出任务，保持完整K。
3. 受限Split-K，例如2或4片，先固定顺序恢复完整FP32 C，再Max(N)、Sum(M)。

第三种增加中间结果与屏障。仅在前两种的有效并行明显不足时评估，不能因为K>=某阈值就无条件采用。[V8，§11]

候选初筛可以参考 `K>=2048、MN<=4096`，但这两个数是V8建议的实验域，不是性能定理。若B较大，本来已有足够独立batch任务，Split-K的重要性会下降。

严禁在各K分片上先Max。`max_n(sum_j C_j[n])`不等于`sum_j max_n(C_j[n])`。

## 11. 第八类：G-dense-fullK，较密集且完整K驻留有价值

K=32/64/128是第一轮静态模板候选，但“完整K能否驻留”不只由K决定，还取决于A宏块、B面板、缓冲份数、对齐和工作区。

### 11.1 四种加载组合必须独立设计与验收

| 布局 | A的局部物理矩形 | X2的局部物理矩形 | 重点 |
|---|---|---|---|
| NN | `[M_macro,K]` | `[K,N_L1]` | A沿K载入，X2沿N批量载入；面板跨多M块复用 |
| NT | `[M_macro,K]` | `[N_L1,K]` | 从实际[N,K]排布构造B1/B2；不按[K,N]地址套用NN加载器 |
| TN | `[K,M_macro]` | `[K,N_L1]` | A与X2分别按其输出轴连续载入；独立处理A的L1→L0朝向 |
| TT | `[K,M_macro]` | `[N_L1,K]` | A转置加载器+B连续K bank加载器；不用完整全局双转置 |

**没有一个表项意味着NT一定最快或TT一定最慢。** 连续轴、局部转换开销、L0需要的分形方向和输入复用都会影响结果。官方ND2NZ与带转置加载能力支持按不同物理方向搬入，但具体参数仍需用CANN9.0实际头文件验证。[R2、R3、R4]

### 11.2 驻留与分片也不能由layout单独决定

对较方正的大矩阵，比较二维M/N分片以及A驻留、B驻留；对明显短M/短N的形状则优先进入前述专用家族。TA/TB决定搬入方向，不自动决定哪个矩阵更应该驻留。

保留V8的四层粒度：核间分片、L1复用、L0计算、CV归约。FP32 C仍使用明确的结果所有权与行/列坐标，不从SDK私有出块序号推测归属。[V8，§1、§9]

### 11.3 K=40/48/72/96等不能被漏掉

它们不属于“其他布局”，而是独立的K长度/尾块特征。可以使用合法的K块并补零，但必须记录补齐浪费和精度。不能把它们全部当作长K，也不应为所有合法K机械编译一份全新算法。

## 12. 第九类：G-dense-Kstream，需要流式处理K的一般矩阵

完整K驻留收益不足或容量不合适时，C在计算侧跨K面板累加，A/B以不同K片推进。完整K完成后才把C交给MaxSim。

### 12.1 中等K与很长K也分别测

建议测试点包括256/512/1024与2048/4096/8192，但不要宣称512是硬件意义上的统一分界。更合适的分界是：驻留容量、K循环次数、局部复制量、实际吞吐。

### 12.2 每种布局使用自己的K面板加载器

- NN：A片为`[M_tile,K_tile]`，X2片为`[K_tile,N_tile]`。
- NT：A片为`[M_tile,K_tile]`，X2物理片为`[N_tile,K_tile]`。
- TN：A物理片为`[K_tile,M_tile]`，X2片为`[K_tile,N_tile]`。
- TT：A物理片为`[K_tile,M_tile]`，X2物理片为`[N_tile,K_tile]`。

同样的K切分，四种布局的连续搬运片段和局部转向不同，应分别选择合法的copy/LoadData配置。不能只让地址计算不同、其他加载参数全部照抄。

### 12.3 独立优化目标

首先比较输入复用、C单/双缓冲和计算/搬出交叠；横向RowMax的优化优先级需由计时确定，不强制沿用小K的全N延后策略。[V8，§10]

V8建议的大K四组资源结构仍作为候选池，但每种layout、dtype和尾块域要分别产生测量记录，不能一个NN/FP16结果代表其余七组。

## 13. 三个横切维度：B、dtype、尾块

### 13.1 B：不是只分“B=1”和“B>1”

B的作用是提供独立任务，合理尺度应相对可用核数和每个batch的工作量判断。

| 情形 | 倾向优先测试 | 注意事项 |
|---|---|---|
| 小B、每batch工作大 | B/M/N合理分核 | 只有一个batch不意味着只能单核 |
| 小B、每batch工作小 | 少核完成，减少跨核汇合 | 不为了占满核而过度分片 |
| 较大B、每batch工作小 | 一核/一组负责batch，或循环多个batch | 尽量避免每batch单独kernel launch |
| 较大B、每batch工作仍大 | batch与M/N联合任务池 | 不机械限定一batch只能用一组 |

不同batch只能一一配对，不允许为复用而默认query相同，也不能把它们变成跨batch笛卡尔积。[P]

### 13.2 dtype：共享地址骨架，分开数值与性能验收

FP16/BF16都是16位存储，可以共享部分地址与搬运结构，但不能把BF16位型当作half数值解释。使用正确的Cast或Cube operand类型，点积与归约保持FP32或题面允许的等效精度。[P；V8，§7]

每个专用家族都要有FP16与BF16分别的正确性、重复性与耗时记录；一个类型过测不使另一个类型自动“已支持且最优”。但未发现差异前也不必机械复制两个完全独立的源文件。

### 13.3 尾块：按物理stride和语义轴分别处理

| 尾块 | 算术处理 | 搬运侧必须另外检查 |
|---|---|---|
| K尾块 | 补零；完整K计算后再Max | TA=false/TB=true时，真实K也是物理行跨度 |
| N尾块 | 无效列不参与Max，必要时填-INF | TB=false时，N影响每个k的行跨度；TB=true时主要是bank条数 |
| M尾块 | 无效行不得进入最终Sum | TA=true时，M影响每个k的行跨度；TA=false时主要是行数 |
| 复合尾块 | 三种规则同时满足 | 源与目的的真实pitch不能混用 |

不能将所有padding都填零：对全负相似度，N尾块的零会错误地成为最大值。也不能读取原输入分配范围之外的对齐区域。[P，§3.6—3.7]

“主体用快路径、边界在同一个kernel内处理”可以是设计目标；在某个loader尚未支持该stride或尾块时，整个调用走已验证fallback仍是必要的正确性保障。

## 14. 真正可执行的分类层次，而不是9个互相覆盖的无序if

### 14.1 先分类，再从该类的候选中选实现

```text
语义分类（精确、无性能阈值）：
    M=N=1         → D
    M=1,N>1       → Q，再按TB分Q-K/Q-N
    N=1,M>1       → S，再按TA分S-K/S-M
    M>1,N>1       → G，再按NN/NT/TN/TT分加载方式

性能分类（用资源模型和测量决定）：
    已验证的小Resident域？
    小输出且长K、现有输出并行不足？
    短M或短N，需要相反的驻留/分核策略？
    完整K驻留是否有价值且容量允许？
    否则K-stream的一般矩阵

每一类内部：
    查找对应dtype、layout、shape/对齐域、核预算的已验证优胜实现
    未有有效优胜记录 → 使用原有正确性路径
```

### 14.2 分类名称不是强制执行器

Q/S家族中极小的bank，也可能仍由历史Tiny或Resident执行器最快。因此新增“语义分类”不等于未经测量就更改V7的Tiny→Resident→Skinny优先顺序。

短M、短N、小输出长K等是会交叉的性能特征。例如M=8、N=128、K=8192同时有短M和长K。应将其作为一个明确子域比较候选，而不是让不同设计者按if先后意外改变结果。

可把以下字段保存在**本地测试记录**中：

```text
semantic_family: DOT / MAX_GEMV / SUM_GEMV / GENERAL
layout: NN / NT / TN / TT / 在退化形状中归并后的有效布局
shape: B,M,N,K
dtype: FP16 / BF16
resource_mode: RESIDENT / K_STREAM
aspect_mode: SMALL / SHORT_M / SHORT_N / DENSE
alignment: M/K/N余数与物理行stride
core_budget: availableCoreNum
executor: 具体经过验证的实现ID
```

正式Host路由只看输入元数据、编译好的配置和返回的合法tiling；不查看隐藏测试序号，不在一次正式调用中让多个kernel赛跑，不缓存计算答案。

### 14.3 可以共享和不应强行共享的部分

**适合共享：**元数据校验、地址公式、dtype traits、唯一输出写入、基础同步组件、已验证的局部归约函数、测试工具。

**不应强行统一：**Q-K与Q-N的计算循环、S类的末端求和组织、短M与短N的驻留方向、fullK与K-stream的主循环、四种布局实际需要的GM→L1/L1→L0搬运方式。

目标是“共用可靠组件，分开关键数据流”，不是为了避免泛化而把每个形状都复制一份完整代码。

## 15. 分场景验收矩阵：先证明分得对，再争取分得快

以下均为本文提出的自建测试形状，不是Judge隐藏用例。[设计]

| 目的 | 代表逻辑形状 `(B,M,N,K)` | 必须变化的轴 |
|---|---|---|
| Dot短K/长K | `(1,1,1,32)`、`(1,1,1,8192)` | B取1/8/64；四种属性应地址等价 |
| Q两种布局 | `(1,1,4096,128)` | TB=false/true；TA也测试但不应改变数学结果 |
| S两种布局 | `(1,4096,1,128)` | TA=false/true；含正负相消输入 |
| 小Resident | `(1,8,16,64)` | B取1/32；四布局、两dtype |
| 短M | `(1,8,4096,128)` | 四布局；Vector复用与薄Cube对照 |
| 短N | `(1,4096,8,128)` | 四布局；X2驻留与旧通用路径对照 |
| 小输出长K | `(1,16,16,8192)` | B变化；完整K、细输出分片、Split-K对照 |
| 密集短K | `(1,1024,2048,64)` | NN/NT/TN/TT独立测 |
| 密集流式K | `(1,512,512,4096)` | 单/双C缓冲、K片大小、四布局 |
| 复合尾块 | `(1,17,19,40)` | 四布局；与临近对齐尺寸比较 |
| 长bank尾部 | `(1,1,4095,136)`、`(1,4095,1,136)` | 连续bank与跨行bank分别测 |

同一逻辑输入应生成四份等值、不同物理布局的连续数组，输出与同一个FP64参考比较。这样才能隔离“布局导致的性能不同”与“值变了、参考也变了”。对退化形状还应专门验证上文的属性归并。

每个子域报告：源码/二进制哈希、具体executor、编译结果、独立绝对/相对误差、重复输出、kernel时延的多轮分布。CPU模型只能核查其已建模的语义和地址，不代替A2计算、缓存和同步。

**选优单位是每个已验证输入域，不是整个版本号。** 一个NN/FP16配置更快，只能使它自己的覆盖域晋升；不能直接把NT、TN、TT和BF16全部切过去。

## 16. 当前应该怎样修改V8的实施计划

V8已有Dot/Resident/GEMV/SmallK/LargeK等分类，但讨论重心仍偏向实现技术。下一步按以下顺序补成完整的场景设计：

1. 固化四布局表、地址公式、退化归并和dtype要求，作为所有实现的共同输入契约。
2. 把原Skinny拆成Q-K、Q-N、S-K、S-M四个独立性能档案；先补目前缺少的跨行bank路径。
3. 将短M与短N单列：前者A驻留并考虑N并行，后者X2驻留并优先M并行，不再统一按SmallK处理。
4. 密集矩阵先按四布局设计搬运器，再在每种布局内部比较fullK驻留与K-stream；静态K是局部优化，不是全部输入的主分类。
5. 小输出长K独立比较并行粒度；尾块与B变化贯穿所有家族，而不是放在最后统一“兜底检查”。
6. 维持旧优胜路径，只有对应子域精度、重复性与同机性能都胜出，才修改路由表。

**本次结论：不是“继续用一个泛化kernel，多加一些shape if”，而是“按照输入的真实访问与归约结构，建立一组可独立验收、可分别替换的专用算法”。** 通用fallback负责未覆盖域的正确性，不再承担所有输入的冲榜任务。
