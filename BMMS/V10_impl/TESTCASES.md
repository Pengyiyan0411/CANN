# V10 离线用例与待提交检查

测试读取实际生成的 F01/F02 单文件，抽取 `BMMS10_CPU_BEGIN/END` 间真实 planner 和设备类。CPU 适配层延用 `next_stage/cpu_shim.hpp`，每次 GetTensorC 清除无效区的初始化标记，主动检测错误读取填充；它采用 FP32 FMA 串行点积及确定性树状 Sum，不是 Cube 指令或流水仿真。

每版正常测试为 32 组 shape/数据配置 × 2 dtype × 4 storage layout × 2 执行次序，共 512 次。22 组基础 shape 采用 [-1/16,1/16] 有界随机数据，另外 5 组 shape 分别使用全负相似度及跨 N 半区交替获胜的构造数据。变更线程启动顺序和 Matmul 分组遍历时，256 对输出要求逐位不变。

| 覆盖 | 代表逻辑 shape (B,M,N,K) |
|---|---|
| 单点与小 N | (1,1,1,32), (3,3,5,40) |
| M/N/K 同时带尾块 | (1,65,137,136), (2,17,19,72) |
| N 尾 32B 对齐与非对齐 | (1,127,80,128), (1,16,1025,40) |
| Split-N 阈值及余数 | (1,129,1023,32), (1,16,1024,32), (1,80,1537,32) |
| 极小 B/M、大 N | (1,1,8192,32), (1,17,8191,32) |
| B 并行与多任务循环 | (64,1,17,32), (7,129,33,32) |
| 最大 M、最大 K | (1,8192,1,32), (1,3,5,8192) |
| 多 M tile 单任务 | (1,513,17,256) |

单独保留 3 个预期失败：B1/M2/N1/K32 的 FP16 和 BF16 强相消，以及相同 shape 的 BF16 乘积溢出。失败会让报告明确保持 `full_domain_precision_accepted=false`；测试脚本退出 0 是正常断言和这些预期失败均复现。

planner 检查枚举 6 个 B、13 个 M、15 个 N、7 个核数组合，共 8,190 个。逐 tile 检查恰好一个任务负责、无空 shard、block 不超核预算、Split-N 触发条件、主机与实际设备类 UB 分配一致性。普通运行同时检查 GM 边界、读前初始化、唯一写入、完整 y、输入不被修改。
