# R01 检查用例与验收边界

标杆：以实际 half/bfloat16 量化后的值做 FP64 dot→max→sum→FP32。
分别报告 abs<1e-4 AND rel<1e-4、组合门槛，零参考且零误差按零相对误差。
不使用 CPU 耗时表示 NPU 性能。

1. 两种 dtype × 四种 TA/TB × 随机正负/全负 C × 两种线程启动顺序。
2. 单完整宏块128×256、全部四个微块，以及144×272、272×528宏尾块。
3. K=256/288/320/352/512/544，覆盖 K1 尾、K0 尾与预取槽复用；K=8192
   用较小强制 producer fixture 验证长循环（公开分支对此小 shape 回退 P01）。
4. B>1、多个 tasks/block、M/N split、cores=1/2/3/8/64；资源最大 M=8192。
5. 全零、输入有负数、重复位模式；捕获源和目标越界、未初始化读取、未回收 flag。
6. 全体公开 guard 的结构边界及输入规模上限；低并行度必须回退。
7. 同一128×256×256 fixture 执行 D01 与 R01 的源码，记录 ND2NZ 字节和调用数、
   L0 字节、Mmad 数、C 输出字节，验证减少来自实际重用。
8. 保留并复现 FP32 已知消去与 BF16 overflow 反例；报告为精度限制，不能删除变绿。

设备最小检查：128×256×256（强制可用核数1，覆盖四 layout 与两 dtype）、
144×272×288（尾块，核数≤4）、512×512×512（并行）。精度通过才 profile
512×512×512 和1024×1024×1024，两版同源数据 ABBA，各轮先预热再采样。
性能结论只读 msprof Task Duration；host_call_mean_us 只作诊断。
