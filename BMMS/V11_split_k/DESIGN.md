# R23：小输出、超长 K 的 Cube Split-K

2026-09-27。基线是已获平台 15/15 Pass 的 R14；R22 的最新反馈为“没用”，没有本轮逐点原始数据。
R23 从冻结 R14 独立生成，R22 的 Native 变更没有合入。

## 证据与决策

用户提供 A01 R03_OFF=112.60 μs，C512/C1024/C2048/C4096 分别为
108.65/113.67/112.77/112.83 μs，正常 R03 约 36–38 μs。
按照用户给出的“仅在 K≥阈值时 bypass R03”的干预逻辑，工作范围取
`4096≤K≤8192, K%32=0`，并结合其 B 系列结论取
`16≤M<128, 16≤N<256, M/N%16=0`。
这些新探针的源码/hash 和完整结果未收到，记录为用户提供的作用域证据；
不能与仓库中名称相似的旧探针自动视为同一文件。

`B=1, M≤64, N≤128` 仍是假说。P02 强制单组后时间不变不能单独证明这些等式/不等式。
R23 支持已报告的完整 M/N 范围及多 batch，不把该假说写进正确性前提。

空间 tile 为 64×128，已知范围每 batch 最多只有 4 个 tile。
如果 `B×tile 数` 小于核数，继续调 pM/pN 无法创造更多独立 C tile。
R23 在这个条件下将 K 分为多段，由独立 Cube 组产生完整局部矩阵，再合并。
如果空间 tile 已足以占满核，R23 不截获，仍用 R14。

## 精确分派规则

host 先保留原 R14 macro route，再尝试 R23，最后回原 R03 和其他 R14 分支。
R23 的 guard 为：

```text
dtype = FP16 或 BF16
1 ≤ B ≤ 64，1 ≤ cores ≤ 64
16 ≤ M < 128，16 ≤ N < 256，M%16=N%16=0
4096 ≤ K ≤ 8192，K%32=0
spatial = B × ceil(M/64) × ceil(N/128)
cap = min(16, floor(cores/spatial), floor(K/512))
S = 不超过 cap 的最大 2 的幂
仅 S≥2 时启用，blocks = spatial×S ≤ cores
```

公开入口继续校验原合法输入、总元素数及 TA/TB 形状。此范围内输入大小不会突破原上限。
核数异常时原入口取 1 核，从而自然回退。
策略仅依赖真实元数据，不读取输入数值、隐藏 Case 编号或评测结果。
FP16/BF16 × NN/NT/TN/TT 共 8 个固定入口，设备代码不调用 host selector。
K1 对照使用完全相同的 guard，选中之后只把 `S=1, blocks=spatial`，用于分离新消费者和 K 并行的影响。

## 计算与归约

```text
u = K/32
K shard s = [floor(s*u/S)*32, floor((s+1)*u/S)*32)
C[s,m,n] = FP32 累加 A[m,k]*B[k,n]，k 属于该 shard
C[m,n]   = 固定二叉树求和所有 C[s,m,n]
Y[batch] = sum_m max_n C[m,n]
```

K 分片连续、无空洞/重叠、长度差至多 32，每片至少 512。
每个 Cube 组恰好负责一个 `(batch, M tile, N tile, K shard)`。
Cube 生产者复用 R03 的 K128 staged loading、ND→NZ、LoadData 与 MMAD 累加流程；
仅调整 K 起止位置和 C 的发布位置。最后一个 K128 块可以是 32/64/96/128。
保留原有小输出 MMAD 的 PIPE_M 依赖屏障。

每个 batch 由一个 AIV 完成最终计算。以 16 行为条带，将各 K 分片有效 C 读入 UB；
按固定二叉树加和，然后才做 N 最大值、M 求和。
N 尾列在加法阶段补零，并在 max 阶段排除；不会读取 GM 中未写入的 padding。
**不能先对每个 K 分片取 max 再求和**，这一般不等价。

没有 AtomicAdd；K 合并顺序固定。但它与 R14 全 K 串行 FP32 累加的舍入顺序不同，
一般输入不保证逐位一致。普通数值检查与有限样本通过不能证明全合法值域精度；
原 FP32 累加/中间结果的极端消去及溢出限制也不能据此标为已修复。

## 发布协议

1. 所有 `blocks` 个 Cube 组均驻留，每组只写自己的永久 partial C 槽。
2. Fixpipe 完成后，通过 MODE2/PIPE_FIX 的 READY=4 通知同组两个 AIV。
3. 每个 AIV 消耗自己组的 READY，然后参加一次 `SyncAll<true>()`。
4. AIV 屏障返回后，每个 batch 的 owner 才读取其他组的 partial C。
5. partial C 不复用、不覆盖，因此不需要 FREE 回传；owner 独立写 Y，不需要第二次全局屏障。

这里的 `SyncAll<true>()` 是 **AIV 内部**屏障，不把它误认为自动等待所有 Cube。
Cube→本组 AIV 的 READY 才是第一层发布依赖，之后 AIV 屏障传播到远端读取者。
`blocks≤cores` 防止尚未调度的组被全局屏障阻塞。CPU 检查覆盖 token、槽所有权、
每个有效 C 元素恰好一次写/读；真实硬件 cache、流水时序仍须平台验证。
API 语义核对见 [Ascend C 同步接口文档](https://www.hiascend.com/document/detail/zh/CANNCommunityEdition/82RC1alpha003/API/ascendcopapi/atlasascendc_api_07_0177.html)。

## 资源和代价

| 项目 | 上界/布局 |
|---|---|
| L1 | 双缓冲 A 32 KiB + B 64 KiB = 96 KiB |
| L0A / L0B | 32 KiB / 64 KiB |
| L0C | 64×128×4 = 32 KiB |
| AIV UB | S×16×128×4 + 16×4 + 2×M×4 + 32，最多 132064 B |
| GM workspace | blocks×64×128×4，最多 2 MiB |
| 有效 C 写入量 | B×M×N×S×4 B |
| A/B 读取量 | 2×B×K×(M×ceil(N/128)+N×ceil(M/64)) B |

K 分片不增加上述总输入读取量，但 C 写回/读取量随 S 增长；尾块可能增加 MMAD 次数。
每批一个 AIV 合并仍可能成为开销。最大 S=16、每片至少 512 是本轮保守起点，
不是已经实测的最优值。

对模型样例 `B=1,M=32,N=64,K=4096,cores=20`：

| 指标 | R14 | R23 K1 | R23 Split-K |
|---|---:|---:|---:|
| Cube 组 | 1 | 1 | 8 |
| 每组最多 K128 次数 | 32 | 32 | 4 |
| MMAD 总次数 | 32 | 32 | 32 |
| 输入读取字节 | 786432 | 786432 | 786432 |
| 有效 C 写入字节 | 8192 | 8192 | 65536 |
| workspace 字节 | 65664 | 32768 | 262144 |
| AIV 全局屏障 | 1 | 1 | 1 |

这是源码工作量核对，不是 Case15 已知形状，也不是 8 倍加速预测。
用户报告的 4.05 μs “最优用时”仅记录为新的页面线索；未用于承诺本版速度。

## 四个独立几何探针

全部从 R14 生成，仅在已报告的小 M/N、长 K 范围内给 R03 guard 增加一次条件 bypass。

| 文件 | 额外 bypass 条件 |
|---|---|
| G01_B1_OFF.asc | B==1 |
| G02_M64_OFF.asc | M≤64 |
| G03_N128_OFF.asc | N≤128 |
| G04_MN4096_OFF.asc | M×N≤4096 |

Case15 若由 36–38 μs 回到约 112 μs 状态，支持对应条件成立；几何条件之间可重叠。
无明显变化仍不能脱离版本、原路径与测评波动直接当作数学反证。
G04 区分语义 family，不影响 R23 正确性，精确 M/N/K 也不是本版运行的必要条件。
这些是诊断提交，故意变慢不代表优化回退。

## 本地验证与设备验证边界

R14、K1、R23 各 116 次普通源码模型执行、58 次重复输出核对；R23 中 96 次命中新路，20 次回退。
K1 普通输出与 R14 逐位一致；Split-K 的二进制分数样本逐位一致，一般随机样本独立对照 FP64 黄金值。
覆盖两种 dtype、四种 TA/TB、长 K 与 K 尾块、两维空间尾块、多 batch、核数不足、负值和零。
每次核对真实逻辑输入/中间结果流量及 MMAD 数量。CPU 模型解码 L0 一次后仍按原顺序逐次 std::fma，
不模拟 Ascend Cube 的实际舍入微架构、异步时序或性能。

对 R23 和 K1 的实际 host/entry 各检查 48 次发射/回退、8 个 dtype/layout 绑定、
1083600 个元数据计划、19092 个分片/任务覆盖组合、36000 次探针条件判断。
故障注入：错误 K 起点、以 max 代替 K 求和、遗漏发布屏障、错误 dtype 绑定，均被检查器拒绝。
具体源码哈希与报告在 CHECKS.json 和 DISPATCH_CHECKS.json。

没有本地 CANN 编译或 NPU 测试。本轮不申请算力，先交付可提交单文件，平台先验收全部 15 点。
有收益时用相邻 R14/R23 重复提交排除波动；无收益时 K1 区分 K 并行收益与新合并开销，
G01–G04 用于补齐几何证据。不要继续重复已无区分力的旧 C 阈值组。
