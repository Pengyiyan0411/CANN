# Case12 宽块优化实测：v12_r62～r64

2026-10-01。**三版已经实现并完成实卡测试，没有合格的通用替换候选；r41 保持主线。本轮不建议提交 Judge15。**

每版均通过 186 配置、602 次精度调用。r62 性能与 r41 基本相同；r63/r64 的缓存收益仍依赖输入形状。新计数器表明：输入加载时间缩短时，算子总时延不一定缩短，不能把全范围优化继续简化为“增加 B 复用”。

## 实现与排查

承接 [上一轮结果](../case12_nmajor_20261001/REPORT.md)。N256 的全 K1536 B 面板需 768 KiB，超过实卡 L1 的 512 KiB；本轮保留宽块，测试指令合并与部分驻留。

|版本|变化|资源与正确性约束|
|---|---|---|
|[r62](../../../BMMS_V12/v12_r62_case12_wide_load_gap.asc)|保留 r30 原分核/消费者；用 LoadData `dstGap` 对调 A 搬运循环，完整 M128/K64 块的 A 指令由 8 条减为 4 条|L1 384 KiB；小 M 尾块沿用原循环；操作数地址相同|
|[r63](../../../BMMS_V12/v12_r63_case12_wide_partial_b.asc)|N-major 连续分核；缓存 B 前 K512，其余 B 以 K128 双缓冲；A 仍 K256 双缓冲|B 缓存256 + B流式128 + A128 = L1 512 KiB；独立管理 A/B 事件|
|[r64](../../../BMMS_V12/v12_r64_case12_wide_cached_stage.asc)|r63 的对照：B 缓存缩为 K256，A/B 均 K256 双缓冲，减少 B 阶段切换|B 缓存128 + B流式256 + A128 = L1 512 KiB；仍保留分别管理的 A/B 事件|

三版均保留 M128×N256、K64 的浮点乘加顺序、完整 K 后 max(N) 再 sum(M)，单 L0C128KiB。L0A双槽32KiB、L0B双槽64KiB。每版新增4个入口，FP16/BF16×TA两种，TB=false。

入口沿用原 R30 条件，并限制 `1280<=M<1536,4096<=N<6144,K==1536`、pitch/family、排除 r41 专属入口。r63/r64 另有原 r59 的 cores/UB 安全条件；未添加根据这次好样本挑选的 N 余数门控。删除新模块和唯一入口 hook，三版都能逐字节恢复 r41。

TPipe 已外置，原实现也已有双缓冲和跨宏块预取。没有发现简单的“缺少双缓冲”错误。实际 dav_c220 实现不支持 LoadData2DParamsV2，本轮使用已支持的 LoadData2DParams；[本地 CANN 头文件](evidence/r62_local_mm_struct.h)和[设备实现](evidence/r62_local_mm_impl.h)已归档。[官方 Load2D 参数说明](https://www.hiascend.com/document/detail/zh/CANNCommunityEdition/910beta1/API/ascendcopapi/atlasascendc_api_07_0251.html)说明了分形搬运参数；本设备是否正确执行由本地头文件及实卡精度共同验证。

## 实际验证范围

设备 Ascend910_9362，ACL 查询20 Cube 核，CANN9.0.0、dav-2201。沿用同一个 C ABI harness 和固定量化输入，无并发 NPU 测量。资源依据：[实际平台配置](evidence/r62_platform_config.log)。

- 每版 164 配置×3次：32 个 N、TA 两种、FP16/BF16，外加全负/零/不同尺度/重复列/成对相消与路由 fallback。
- 每版额外22配置×5次：M1344～1520 的尾块组合、两种dtype、精确 K 正负配对。
- **全部通过**。参考为真实 FP16/BF16 输入量化后的 CPU FP64 计算；阈值 `1e-4+1e-4*abs(reference)`；每次调用前 NaN 毒化输出。
- 各版最大绝对误差0.0410701，出现在大尺度输出；最大误差/容差比例0.076294，小于1。精确K配对的4配置误差为0。
- r62：[64组装载映射检查](AUDIT_R62.json)。r63：[7组事件序列、3072操作数切片和2048分核覆盖状态](AUDIT_R63.json)。r64：[7组事件序列、1536操作数切片](AUDIT_R64.json)。CPU事件模型不等于硬件竞争证明。

本轮没有精度失败或源码误改基线。完整精度日志在 [evidence/results](evidence/results/)。由于性能未入围，没有跑新的 mssanitizer，也没有运行32配置完整性能筛选、96配置性能留出或 Judge15。不能把精度覆盖写成性能留出通过。

## 性能对照

预先固定8配置：B1、M1280、K1536、TB=false、FP16，N=4096/4160/5120/6080，各两种TA。每个候选都与当时的 r41 串行 ABBA：每版2个窗口，每窗口每形状30次，丢弃前5次。取 msprof 完整混合 kernel task duration，包含设备端归约与同步，不含 host 分配/释放；不是无 profiler 测量。

已核对实际 kernel 名，全部8组命中对应新增入口。性能运行也验证精度。官方参考实现无法在相同合成输入上执行，官方性能栏为 N/A；历史截图不同隐藏输入的时延不用于计算本表加速比。

## 计数器揭示的区别

额外对两个代表形状采集 PipeUtilization，r41/r63/r64 每形状5次、丢弃首个。下面为剩余样本中位数，单位μs；原始结果：[r64_counters.json](evidence/results/r64_counters.json)。计数器测量有额外开销，不能取代上方轻量 task-time 结果。

|样本/指标|r41|r63|r64|
|---|---:|---:|---:|
|N5120、TA0：完整 task|94.42|99.13|98.99|
|同上：AIC MAC|75.07|75.88|76.09|
|同上：AIC MTE1|57.03|60.44|59.86|
|同上：AIC MTE2|66.77|60.19|65.50|
|同上：AIC scalar|51.43|52.27|48.65|
|同上：AIV scalar|13.70|15.65|14.48|
|N6080、TA1：完整 task|147.99|135.85|143.61|
|同上：AIC MAC|91.17|90.79|90.93|
|同上：AIC MTE1|66.05|66.63|65.79|
|同上：AIC MTE2|133.69|105.88|120.04|
|同上：AIC scalar|62.50|62.19|59.16|

这些流水线时间有重叠，不能相加，也不是可独立扣掉的成本。当前证据支持：

1. **N5120/TA0 的输入优化没有改善总时延。** r63 的 MTE2 已从66.77降至60.19，但 task 反而增加；MTE1、AIC总时间和归约收尾仍有额外成本。它更接近计算/流水约束，不能从 B 请求减少推导加速。
2. **N6080/TA1 确实有可利用的输入加载瓶颈。** MAC基本不变，r63 的 MTE2 减少约27.81，task减少约12.14；这是局部收益的机制证据。该形状的好结果不能代表未知的隐藏 Case12。
3. **控制指令更少不等于更快。** r62 指令数减少但时间不变；r64在 N5120 的 scalar 比基线还低，task仍较慢。r64缓存变小也削弱了 N6080 的输入收益。
4. **下一步应区分输入受限与计算/流水受限的形状。** r63仅适合保留为前一类的研究分支。若今后缩小入口，必须预先冻结基于metadata的条件、验证独立N/M/dtype性能与实际覆盖，不能只挑本表最快的几个尺寸。

N256 宽块已避免上一轮 N128 造成的大部分额外内部搬运；这一步仍不足以得到通用收益。r64也不是“完全消除额外事件”的版本：A/B阶段尺寸对齐了，但READY/FREE仍分开。这是下一轮可独立测试的控制项，收益尚未知，不写成已解决。

## 决策与文件

本轮三项对照结束，**不晋升、不覆盖 r41，不把 r63 的单个样本 +8.5% 当作 Case12 的提升**。保留完整源码供复核，暂不建议消耗正式提交。

下一轮优先检查新分核的额外收尾和 A/B 事件成本；若继续 B 缓存，应先证明可获益子域，不能继续全范围加缓存。对旧 r30 的计算受限形状，则应保留原分核和归约结构，单独考察流水气泡，避免用新的20份partial合并引入成本。
