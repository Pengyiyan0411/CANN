# V12 第二轮 NPU 实验：r07 / r08 / r09

2026-09-28。**主线继续冻结 r03；保留 r07 为小幅收益候选，r08/r09 不合入。** 本轮没有获得足以宣称明显冲榜提升的结果，也没有用最快单次时间替换主线。

## r07：收益存在，但幅度小于初筛

原 R06 对同一 M 微块的两个完整 N 微块分别搬运，并初始化随后完全覆盖的 UB 数据。r07 合并 DMA：一个 AIV 读两个微块中的自有行，在 UB 直接合并，再做行最大值。

保留原 producer、planner、K 累加、ring credit、workspace 和最终求和顺序。守卫为原 R06 合法域内：B=1、M/N≥1024、N%256=0、1024≤K<1536。合法 M 尾块仍处理；其他元数据走原路径。新 DMA 地址枚举核对147456项，显式 consumer UB 在 M=8192 时为131744字节。

轻量 profiler 初筛，四个 FP16/NN 合成输入的耗时下降约2.7%–5.7%。但进一步采用无 profiler 的设备事件对照后，幅度较小。因此以更保守、可重复的结果描述收益。

下表为**第二个新进程复验**。每个样本100次热身，20对交替窗口，每窗口64次直接 kernel launch；每个窗口结束检查输出。表中降幅是配对窗口降幅的中位数，不能由两个时间中位数精确反推。

第一轮同类事件测试也全部为正，约0.5%–2.1%。四个筛选形状的 A/A 校准单窗口差异约在±0.3%内。

**计时边界：** 设备事件程序在同一个二进制中交替调用原 kernel 和候选 kernel，共用预分配 workspace，包含设备流上的调用间隙，省略公开 host dispatcher 内的规划/分配/同步/释放。它用于确认改动的效应，不能作为正式比赛成绩。轻量 profiler 则运行完整 `run_kernel`，统计 kernel task duration；两种模式分别保存，不混为一个绝对时间序列。窗口相关性仍存在，没有把连续调用当成大量独立样本，也没有给出夸大的置信区间。

## 守卫外回归对照

抽查 N=2064、K=1536、B=2 和一个 residual-small-spatial 形状。第一轮两组出现约0.6%的变慢，因此额外做了5个交替窗口，未直接忽略。

| 控制形状 B,M,N,K | 首轮配对变慢中位数 | 复验配对变慢中位数 |
|---|---:|---:|
| 1,1040,2064,1056 | -0.629% | +0.076% |
| 1,1024,2048,1536 | +0.640% | -0.460% |
| 2,1024,1024,1024 | +0.557% | -0.057% |
| 4,64,128,256 | +0.001% | +0.459% |

正号代表变慢。复验方向发生变化，没有复现固定退化。最后一项约4.3μs，其两个版本跨窗口中位数均为4.36μs。这里说明抽查结果，不能替代隐藏15点回归，也不能以“源文件原路径逐字节保留”保证跨编译产物性能完全不变。

## Native：两个假设均未带来稳定收益

基线 profile 在 M=1024/N=48 与 M=2048/N=64、K=128 的样本上显示：aic_mac_time约0.096–0.209μs，而aic_scalar_time约5.1–5.9μs；AIV总时长约6.6–8.1μs。数据支持检查调度、等待和末尾收敛，但不足以单独定位关键路径。

- **r08**：省去完整行数组的 GM 往返，改成各 AIV 局部求和。改变浮点加法分组，但独立 FP64 校验通过。新增局部 ReduceSum 和小计收集没有在所有规模上换来收益。M=4096 的部分样本回退；M=8192 的轻微改善不稳定。停止该方案。
- **r09**：在 B=1、N=48/64、K=128、单波次且存在多 M 微块的 plan 中，将不变 B 的 L0B 填充降为每核一次。消费者及求和顺序完全保留，L0B分配从64KiB减为32KiB。8个筛选样本的事件配对降幅约-0.07%到+0.10%；12个留出样本约-0.20%到+0.18%，没有超过噪声。减少加载指令数量不等于缩短关键路径，停止该方案。

这两次失败不证明 Native 已到硬件下限；它们只否定本轮具体改动在这些样本上的收益。下一轮不重复扫描同类参数。

## 正确性与内存检查

参考值来自实际量化后的输入，以 CPU FP64 计算 matmul、完整 N 域行 max、M 维 sum。要求所有输出有限且满足 `abs(error)<=1e-4+1e-4*abs(reference)`。覆盖 FP16/BF16、四种转置、空间/K尾块、ring反复复用、零值、全负输出、大动态范围、相同列及守卫内外样本；独立运行每例3次、调用前填充 NaN 输出哨兵。

r03/r07/r09 的182例最大误差/容差比均为0.0029901；r08 的141例为0.0016642。设备事件测试另验证连续复用同一 workspace 后的每窗口输出。

按 ascendc-mssanitizer 技能，直接对实际 C++ 程序执行 memcheck。r07 的 B1/M1040/N2048/K1056/FP16 NN 尾块例正常完成并通过数值检查，没有 ERROR 或非法访问报告；但存在60条 `FFTS_BASE_ADDR` 未恢复默认值警告。用 r03 相同输入复查，得到同样60条警告。因此没有把结果标记成“零警告”，也没有把这些警告归因于新增 DMA。原始日志全部保留。该单例 memcheck 不等价于完整 race/init/sync 检测。

优化技能引用的 code-gen 参考文件未安装；本轮核对了实际 CANN 9.0.0 的 queue、DataCopy 和 ACL event 头文件/实现，并以真实编译及设备测试验证。未依据不存在的文档编造 API 能力。
