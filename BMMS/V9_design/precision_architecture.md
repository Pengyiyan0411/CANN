# V9 数学与架构独立复核

2026-09-26。仅阅读题面、当前审计、路线重审与 P01 消费者代码，并在 CPU 上计算下述反例；未编译 Ascend C，未运行 NPU。本文检验下一版的约束，不将数学推导当作设备性能证据。

## 结论

“完整 K 后交付 C、在线 N 最大值、最后按 M 求和”是合理主线。它可以扩大现有 Native 的覆盖范围，但必须同时解决三件事：真实可行的 L0C 驻留与循环顺序、不能丢行信息的跨核合并，以及 FP32 中间 C 相对完整 FP64 golden 的精度边界。仅把 K32/64/128 模板换成 K 循环，不足以解决这些问题。

题目明确允许 FP32 累加，但这不构成全合法数值域都满足独立绝对/相对 1e-4 的数学保证。P01 也不是已经证明全域正确的兜底。下一版应保留它作为已有评测记录的对照，新增准确的数值验收和失败隔离，避免把已有 15/15 Pass 扩写为全域认证。

## 1. 允许的分解与必须保留的信息

设完整点积为 C[m,n]，N 分片集合为 J_s。逐行保存 r_s[m]=max(n∈J_s) C[m,n]，然后计算 sum_m max_s r_s[m]，与数学目标一致。每个 N shard 不能先把 M 求和成一个标量。

可嵌入 K=32 合法输入的精确反例：C=[[10,9],[9,10]]。正确值为 20；两个 N shard 各自 Sum(M) 都为 19，对这两个标量取 Max 得 19，求 Sum 得 38。构造时令 A 的前两列为单位矩阵、其余 K 项为 0，B 的前两行为 C。

Split-K 可以作为矩阵乘内部的分工，但必须先对每个 (m,n) 合齐所有 K 部分和。例：两段 K 的结果分别为 [10,0] 和 [-10,1]，完整结果为 [0,1]，Max=1；先取局部 Max 再相加会得到 11。K=32 时仅使用 k=0、k=16 即可构造，全部输入可用 FP16 精确表示。

对于有限 FP32 值，N 维 Max 的分块/合并不累积加法舍入；在线 Max 本身不需要补偿算法。若点积误差满足 |Ĉ[m,n]−C[m,n]|≤ε_m，则行最大值的误差也≤ε_m，即 Max 的数值是 1-Lipschitz 的。近似计算可能改变获胜列，但本题不输出列索引；不能把“近似并列”夸大为无界输出误差。最终仍需控制所有行误差的累积和 Sum(M) 的舍入。

M 尾行不能进入最终 Sum；N 尾列必须从 Max 排除，填 0 在全负相似度时错误；K 补零不能遗漏合法余量，尤其 K%8=0 但 K%16≠0 的情况。各 batch 必须完全隔离。

## 2. FP32 C 是实质性精度边界

CPU 已计算以下合法 FP16 反例：B=1,M=8192,N=16,K=32，A 的行按下式交替，B 的 16 列相同：

- A[2i,:]=[1,2^-12,0,…]。
- A[2i+1,:]=[-1,0,0,…]。
- B[:,n]=[1,2^-13,0,…]。

每对行的精确点积是 1+2^-25 和 −1。完整 FP64 golden 为 4096×2^-25=2^-13=0.0001220703125。即使点积先精确计算，只要将每个 C 元素单独转成 FP32，再交给归约，行值就会变成 1 和 −1，最终得到 0。

本次 CPU 结果：绝对误差 0.0001220703125；独立绝对/相对门均失败；组合容差 1e-4+1e-4×|golden| 也失败。此处甚至使用 FP64 完成后续 Sum，仍不能恢复丢失的 dot 低位。这个反例不是对某个 NPU 二进制的执行结果，而是对“仅输出一个 FP32 完整 C 值，之后再加强 epilogue 即可全域满足 golden”的反证。

题面背景提及上游归一化，但正式数值约束没有给出逐 token 范数的可验证范围。上例的单位分量稍超过单位范数；即使把 A、B 均乘 1/2，使所有相关向量范数小于 1，仍产生非零 golden 而 FP32 C 路径输出 0，独立相对门依然失败。不能由背景自行引入严格输入幅值承诺。

因此设计文档应分开表述：

1. FP32 Cube 路径符合允许的累加类型，是首选性能候选。
2. 它尚未获得全部输入的误差证明，必须跑完整 FP64 oracle 和抵消集。
3. 补偿最终 Sum 有价值，但只修复 Sum 引入的误差；不能宣称修复了 C 已经舍弃的低位。
4. 若设备试验确实需要更高精度，应针对失败类别评估保留 hi/lo 点积、精确残差或更高精度重算。不能凭 host shape 知道任意输入是否发生抵消，也不能把未经证明的数据相关准确性分支称作可靠兜底。

不建议现在为这个最坏情况直接放弃 Cube 或实现全域高精度通路：先将它列入正确性集，在真实平台核对误差和评测口径，再决定投入。精度文字存在的矛盾应显式保留，不能通过篡改 golden 消失。

## 3. M=1、N=1 的降阶边界

- M=1：是多条长度 K 点积的最大值。没有一般性的代数办法免除读取任意稠密 B；可通过 Vector GEMV、批量点积和布局连续方向降低启动、填充与归约成本。
- N=1：是多条长度 K 点积的求和。数学上可写为 sum_k (sum_m A[m,k]) B[k]，但改变浮点归约顺序，且题面要求先 MatMul 再归约。不要仅凭代数等式采用“先对 A 求和”的路线并宣称数值合规。
- M=N=1：退化为 Dot，适合轻量固定树/补偿归约；仍要完成全部 K，不能仅因小输出就忽略大 K 精度。

例如 BF16 可精确表示 [2^24,1,−2^24]。N=1、B 的对应分量为 1 时，完整 FP64 golden 为 1，按该顺序用 FP32 预聚合 M 得 0。此例既说明预聚合有风险，也说明普通 FP32 最终 Sum 有同样风险；它不是在证明原始顺序天然准确。

这些退化分支的大幅提速应来自更适合形状/布局的执行组织。对于 N=1，先聚合 A 减少乘法数不等于降低读取稠密 A 的渐近复杂度；仍至少读取 O(MK) 输入。不要把它误称为普遍的数量级算法降阶。基于近邻、近似筛选或不带误差证明的提前剪枝不适合精确题意。

## 4. 有限输入不意味着有限输出

FP16 的最大有限绝对值为 65504。依据题面 M,K≤8192，有 |y|≤M K×65504²≤2.8794896989447782e17，低于 FP32 最大有限值。因此 FP16 输入的这项粗上界排除了数学结果因幅值溢出 FP32。

BF16 不同。取 M=N=1,K=32，仅 k=0 的 A、B 都为 2^64，其余为 0；2^64 是有限且 BF16 精确可表示的数，但乘积为 2^128，转 FP32 为 Inf。CPU 已核验最终转换不有限。完整 FP64 点积本身仍有限。

由此可见，“允许任意有限 BF16 输入”“golden 最后转 FP32”“输出绝不能 Inf”三条文字若同时按全域理解，并不相容。不能用 clamp 消除 Inf，因为会偏离指定 golden。应将它记为题面数值域缺口；当前正常数据的开发可以继续，不需要因此占卡或强行发明裁剪规则。

## 5. Dense Full-K 架构的关键反问

最需要写清的是循环顺序和同时驻留的 C 范围。不能免费同时获得：大 A/B macro 复用、任意长 K 的流水、全部 C 在 L0C 保持至完整 K、双 C 缓冲。

例如 AM=128、BN=256 的 FP32 C 就占 128 KiB；若对这个整个 macro 使用两个独立 C 槽，需要 256 KiB。这个算术值必须对照实际 A2 可用 L0C 容量。只保留 64×128 的 C 微块可以减小 C 驻留，但切换下一个微块后可能需要重新读/搬完整 K 的 A/B。改用 K 外循环来共享大输入 panel，则要同时保存更多 C 或将未完成的 C spill 出去，再增加流量与舍入。

建议把两条候选明确区分，而不是在一张图中同时假定所有好处：

| 候选 | 确认保留的特性 | 必须计入的代价 |
|---|---|---|
| 微块 output-stationary，完整 K 后出 C | C 不在 K 中途出片；生命周期简单 | 不同 M/N 微块的 A/B 重搬；长 K 下 L1 不能常驻全输入 |
| 较大 macro C 驻留，K 分段复用输入 | K panel 的 M/N 复用更大 | C 占用提高、可并行槽位变少；超容量必须缩块，不能隐式假定 spill 免费 |

A2 GM ring 即使只占两个槽，也可能对每个 C 元素发生一次写和一次读。容量 O(tile) 不等于总 C 交接流量 O(tile)。在没有压缩或直接片上交接的前提下，应把约 8×B×M×N 字节的 FP32 C 交接总流量计入模型，而不只计算 workspace 峰值。

“扩大 Native 范围”也不保证所有新增大 K 都快。大 K 原高阶 Matmul 可能已有较好的输入复用；新手写实现若为保持 full-K C 而重复搬运，将可能退化。应保留同 shape 的矩阵乘主体对照，衡量 Cube 主体与融合增量各占多少。

单次 launch 的全局合并还要求：所有实际参与核到达同一同步点；不把跨核等待放在尚有未调度逻辑任务的循环内部；工作划分不能让生产者等待一个永远不会运行的消费者；GM 数据可见性先于完成标志。现有 P01 是物理 worker 循环处理多个 task 后执行 SyncAll，再按固定顺序合并。下一版不能在改成更大虚拟任务网格时直接照搬假定。

确定性要求固定 Sum 树/遍历顺序。原子浮点 Add 即使最终写入一个标量，也可能随到达顺序变化，不应作为未经证明的性能捷径。

## 6. 最小验证建议

无需 NPU 可以立即检查：上述 N-shard、Split-K、FP32 C 丢失低位、BF16 溢出反例；四布局的逻辑映射；精确的 producer/consumer tile 序列；每个 C 的首个 K 初始化与最后 K 交付；workspace 区间；环缓冲每槽最多在持有 credit 时复用。

还需修正大范围 golden 的内存策略。当前 precision_gate.golden 直接物化 B×M×N 的 FP64 C；合法 B=64,M=N=8192,K=32 时仅 C 就约 32 GiB。本次另增 [blocked_oracle.py](blocked_oracle.py)，按 batch/M/N 分块计算，每块保留完整 K 的 FP64 dot，保存 FP64 每行最大值，最后才按 M 求和并转 FP32；没有修改既有 precision_gate。已通过双 dtype（BF16 为先量化再解码的 FP32 存储值）、四布局、三组分块大小共 24 次与未分块 oracle 的输出位模式比较，以及抵消、全负、3 个无效输入检查。这是小范围 CPU 一致性检查，不等于所有 FP64 BLAS 分块归约在任意数值上位模式一致，更不等于设备验收。

首次有卡后，先做覆盖新增机制的少量正确性运行，再测速度：

| 家族 | 代表 shape (B,M,N,K) | 核心问题 |
|---|---|---|
| aligned 长 K | (1,128,256,1024) | K 循环是否正确累加、C 仅在最后交付 |
| M/N/K 尾部 | (1,65,129,1000) | 三维尾块、N 负无穷掩码、奇数 M 的 AIV 分工 |
| 多 batch、大 K | (2,17,257,8192) | 最大 K、多 N tile、batch 隔离 |
| 抵消精度 | (1,8192,16,32) | 上述 FP32 C 反例与最终 Sum 误差分离 |

前三族应覆盖双 dtype、四布局，加入全负与重复位模式；第四族不是性能标杆，是明确的精度压力。环缓冲另选择使每槽复用至少三次的调度，并覆盖 tasks>physical workers 的循环。不必首次上卡就穷举 tiling；先验证 producer-only 对照、原融合、候选融合在同输入上的主体成本和交接开销，再据结果选择一个主要瓶颈。

这些实验不需要知道隐藏 15 点的 shape。它们能证明新机制是否值得扩大覆盖；不能证明 Case 8/15 必然属于某一族，也不能把几个局部加速倍数直接换算成预期排名。

## 7. D0 与实际提交的精度门禁补充

**D0 仅定义为吞吐与集成诊断候选，不单独进入可提交路由。** 单 FP32 C 的信息丢失已经由离线反例证明，不需要等上卡再“发现是否有风险”。D0 的设备实验用于回答计算、搬运和同步成本；真实提交候选必须包含 D1 精度机制，并按该完整实现衡量性能。已有 P01 可以继续作为历史对照，但不是精度认证后的默认兜底。

### 方案 A：带误差界的选择性高精度重算

1. 对每行输出保存近似 row-max 和可信误差区间。若每个点积有界 ε[m,n]，则真实行最大值位于 `[max_n(Ĉ−ε), max_n(Ĉ+ε)]`。可用覆盖全列的逐行 ε 简化，但误差界必须覆盖真实 Cube 累加模式、输入范围、舍入和下溢；不能未经核验直接套某个 γK 公式。
2. 将所有行区间合并成 batch 输出区间，并控制区间端点计算及最终 Sum 的舍入。还须将指定 FP64 reference 的运算误差与最终 FP32 转换纳入认证口径；不能仅给实数数学结果一个经验估计。
3. 只有当候选 FP32 输出对区间内所有可能的 golden 都满足绝对和相对门槛，才直接接受。若区间跨越零，相对误差认证通常不成立，必须缩小区间，不能用大分母或 epsilon 地板隐藏问题。
4. 未通过认证时，按固定顺序重算贡献较大不确定性的行；简单版本重算该行全部 N 个点积。若只重算候选列，每个被排除列都必须满足其上界低于某个候选的下界；仅重算 top1/top2 不够。重算结果仍保留高低位或区间至最终 Sum，重新做 batch 认证。

相对粗但便于形成合法上界的量是 `q_m=sum_k |A[m,k]|*max_n |B[k,n]|`，它覆盖该行所有点积的绝对乘积和。计算 q_m 自身也要保守处理舍入；界太宽会使大量行重算，直接失去吞吐收益。因此第一次实现应记录认证通过比例、重算比例及完整延迟，以决定是否保留此路线，不以 D0 的单独速度作为最终收益。

该机制必须在提交允许的一次 launch 内完成。可以设计固定阶段：生产近似 row-max/区间→同步→决定需强化的行→分配给已有物理 worker 重算→固定序合并。不能在需要重算时临时依赖 host 再发第二个 kernel，也不能让尚未完成生产的 worker 等待未调度的重算任务。复杂度和额外同步都是需要计入的代价。

### 方案 B：从点积开始保留高低位

完整点积产生 `(hi,lo)`，N 维比较保留对应获胜点积的高低位，M 维固定树累加高低位，最终才舍入为 FP32。这样至少不会在 C 交接处确定性丢掉上述反例的残差。

但不能把普通 Cube 的单 FP32 C 包装成 `(C,0)`，也不能只对多个已经舍入的 K 分段结果求补偿，就声称恢复了段内丢失的信息。必须从乘积/累加阶段获得可信残差；例如 FP16 产品可由 FP32 精确表示，再用带残差的 Vector 求和作为正确性优先原型。BF16 还需单独处理乘积范围与下溢。hi/lo 本身也不是任意输入下的最终精度证明，应保留残余误差控制，必要时提高精度。

### 明确的推进与停止条件

| 门 | 可继续的结果 | 不满足时的行动 |
|---|---|---|
| D0 语义/精度检查 | 已知反例失败被准确记录，其他逻辑错误隔离 | 不把 D0 标为可提交；继续用于结构诊断 |
| D1 原型 | 修复上述反例，完整 FP64 oracle 检查通过；误差来源与算法可解释 | 修复点积与最终 Sum，不切回同 shape 的 FP32 路径掩盖问题 |
| 区间认证方案 | 有保守界、零附近规则、失败重算路径，所有路径明确终止 | 无可信界就不能声称运行时认证；改为统一高精度原型或继续研究 |
| D0+D1 性能 | 计入认证、重算、额外数据与同步后仍优于对照 | 更换精度方案或保留为诊断成果，不拿 D0 耗时冒充提交耗时 |
| 发布 | 完整候选通过既定精度集、确定性和实际设备验收；明确未证明的全域边界 | 不将未完成的精度路径合入实际提交 |

如果高精度机制仍不能通过固定精度门，就没有诚实的“临时 shape fallback”可以消除同一 shape 内的数据相关抵消风险。此时应保留研究结果、停止发布候选，明确尚未完成精度路线，而不是放宽 oracle 或把已有 15 点通过记录作为替代证明。
