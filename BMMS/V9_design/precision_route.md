# V9 数值路线与提交边界

主线 D/S 是执行组织，Q 是它们共同必须面对的数值条件。已知 FP32 C 反例意味着**裸 D0 是吞吐/集成诊断内核，不应单独进入可提交路由**。S 的不同归约次序可能改变误差，也没有自动获得正确性证明。不能等上卡后才承认已经离线成立的精度缺口。

这里给出下一实现阶段的决策设计，不宣称已完成高精度内核、误差证明或设备验证。正式题目允许 FP32 累加，又以完整 FP64 golden 判定；字面任意有限 BF16 还与有限输出要求存在冲突。本地应保存这种差异，不通过改 golden、裁剪输出、按输入数值挑测评逻辑来掩盖。

## 1. 首先把诊断候选和提交候选分开

| 产物 | 用途 | 当前允许结论 |
|---|---|---|
| D0：单 FP32 C 的全 K dense | 编译兼容、流水、矩阵乘主体成本对照 | 可研究，不可声称全域精度成立 |
| S0：固定顺序 Split-K | 低占用输入的并行方式对照 | 可研究，须合齐完整 C 后 Max |
| Q1：带误差界的快速计算与高精度重算 | 研究能否兼顾快速路径和严格误差 | 尚需硬件舍入模型、界的计算成本与后备实现 |
| Q2：从 dot 开始保留 hi/lo | 研究避免在 Max 前不可逆丢掉低位 | 尚需实现及剩余误差分析；双浮点不等于精确 |
| 可提交 V9 | D/S/V 的执行主体与可接受数值实现组合 | 必须整体通过实际输出、精度、确定性、性能验收 |

已知缺陷不靠 P01 fallback 修复：相同 shape 内能同时存在普通输入与强消减输入，单纯 shape 分流不能证明数值安全。P01 是历史对照，不是高精度后备。

## 2. Q1：先研究误差区间是否足够便宜、足够紧

若可以为每条已计算点积建立可靠区间 `C[m,n] ∈ [l[m,n],u[m,n]]`，每行最大值位于 `[max_n l, max_n u]`。它不要求确定哪个列赢，也不能只观察 top1/top2 的数值差；未入选列的误差区间同样可能影响真最大值。

将各行区间相加，并计入区间计算和最终 Sum 本身的舍入，得到精确实数结果区间。还要覆盖所指定 FP64 golden 的计算误差，再映射为最终 FP32 golden 的可能区间。只有候选输出相对这个区间里的全部可能 golden 都满足所采用误差门槛，才有资格接受。区间跨0、近零、溢出或界不够紧时不能草率通过。

构造误差界之前必须核对目标 Cube 的实际累加/舍入语义。标准 `gamma_K * sum(abs(a*b))` 形式只能在其前提成立时采用；计算绝对乘积和本身也有成本和误差。用范数上界可以便宜一些，但常常太松，触发大量重算。没有经验证的界时，本分支只是研究算法，不能把经验阈值标成认证。

不能认证时，重算相关行的完整 N 范围；若要删掉某些列，必须有它们不可能超过当前最大值的区间证明。对近零最终和，可能需要重算整个 batch，不能只修最大绝对值的行。

单次 launch 下的重算必须在设备内完成：快速路径写出候选/区间元数据 → 统一合法会合 → 设备根据数值误差需求执行高精度计算 → 固定顺序最终归约。其判断是保证算术精度的运算步骤，不是 host 根据输入值识别隐藏用例。所有已启动核必须遵守相同同步阶段，不能按数据分支跳过全局 barrier。

退出条件：如果可信界的计算、元数据搬运、统一会合和重算使整体成本无竞争力，就否定 Q1 的具体实现；不能删掉认证步骤留下看似更快的“优化版”。应记录认证比例、重算行数、重算成本与完整总耗时。

## 3. Q2：低位必须从点积阶段产生

如果需要保留 hi/lo，就从乘积与加法阶段保留残差，随后以明确的双分量规则比较完整 dot、保存行最大值并进行最终求和。不能先接受 Cube 的单个 FP32 C，再补一个 `lo=0`。

FP16 两数乘积在 FP32 中通常有足够有效位，但仍需分析整个值域、求和误差及目标指令行为；BF16 还必须分析乘积指数范围、下溢与溢出。Vector error-free transform、分段补偿、或有依据的残差重算都是实现候选，不能直接宣称某个两分量技巧等价 FP64。

即使 hi/lo 改善大量例子，极端消减下仍不能凭经验宣称全域相对误差保证。剩余不确定的输入需要更高精度后备或明确的真实评测数值契约；这项边界必须保留。若严格全域实现成本不可接受，应如实报告约束与性能的矛盾，不能把已知错误路径包装为完成。

## 4. 最小的下一步

先离线固定反例、零/负值、长K、近零和、四布局及两个输入 dtype 的真实存储值。K32的 FP32 C 反例可直接补零到 K256/8192，不能靠扩大 K 路由绕开；256条规格已用K256版本覆盖新 dense 域。

实现阶段先完成 D0/S0 的可测主体与 Q 的最小算术实验，各自标明用途。未通过精度的诊断内核可以在单独标记的安全普通输入上测吞吐来比较架构，但该结果绝不算“候选通过”、不进入正式成绩表。实际提交前必须验收含 Q 的完整程序，不能用裸 D0 的时间宣传组合后的性能。

目前 Q1/Q2 尚未证明哪条在本题划算；这是真实未决项。无需 NPU 就能确定的是：继续仅优化 FP32 epilogue 不能解决已经丢失的 dot 低位。算力应首先验证接口、真实算术行为和组合成本，而不是重复验证这条已知数学事实。
